# AU-433｜财务、发票与渠道初始模型

## 范围与方法

- 主审文件：`02_platform_pingtai/database/supabase/migrations/20260821022000_create_finance_channel.sql`。
- 交叉核对：后续索引、范围授权和个人发票 scope 迁移，以及 Commerce 财务、发票、渠道同步和对账实现。
- 本批为静态迁移语义与调用关系审阅；未执行数据库重放、构建、测试、外部渠道调用或线上操作。

## 运行结论

财务域建立账户、分录、凭证、期间、对账、结算、策略与对账单。`finance.enforce_balanced_journal` 在凭证首次过渡到 posted 时核对借贷总额相等且非零，并写入 posted 时间；后续 Finance 运行链查询已过账凭证、生成期间报表和执行对账。

发票域以加密抬头/税号字段及 token 保存档案，记录申请、单据、行和状态事件；后续迁移补充个人 owner scope 与快照模型，Commerce 发票操作和结算报价持续使用。

渠道域保存连接的超时、并发、限速与熔断配置，且以局部唯一索引限制单连接同类 active sync，以 provider+kind+idempotency key 约束外部操作重放。映射、来源记录和对账单为供应商同步与财务对账提供数据责任。

## 审计结论

- G0：复式记账、发票敏感数据保护和渠道幂等同步的基础关系模型，不是删除候选。
- 当前运行列与权限模型由后续迁移扩展；不得仅以初始定义不同于现有运行 SQL 推断迁移闲置。
- 未执行实际过账、渠道重试或密钥访问验证；这些行为保持未验证。
- 本批未新增 P0–P3。
