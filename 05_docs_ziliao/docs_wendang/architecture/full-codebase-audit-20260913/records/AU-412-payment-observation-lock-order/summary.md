# AU-412｜微信支付观察原子落账

## 范围与方法

- 主审文件：`02_platform_pingtai/database/supabase/migrations/20260820127700_payment_observation_lock_order.sql`。
- 交叉核对：库存付款提交、支付 outbox 中继和后续查询结果适配器/契约测试。
- 本批为静态调用链与迁移语义审阅；未执行数据库重放、构建或线上操作。

## 运行结论

核心观察函数以订单优先锁定订单、支付和微信尝试，并对供应商事件键、交易号、金额、商户、应用、付款人散列及完整证据摘要实施严格幂等校验。成功付款在同一边界内更新支付、订单、子订单和库存提交；库存冲突会 fail-closed 地进入对账状态而不是误履约。终态失败会释放有效预留并取消订单；每个实质状态变化都写观察事实与审计记录。

函数仅作为内部核心，直接执行权限被撤销；后续查询/通知适配器通过受限入口调用。迁移还显式断言旧微信专用 outbox/函数不存在，防止新旧支付运行时并存。

## 审计结论

- G0：这是支付观察、库存一致性和可靠出站事件的原子边界，不是删除候选。
- 本批未新增 P0、P1、P2 或 P3；未运行验证均已明确保留为未验证状态。
