# SFL 全项目统一 AI 发布引擎标准 V1.0

版本状态：候选标准
适用范围：`zdt-next` 及后续接入同一发布协议的项目
上位约束：SFL 1.8（完整收录并取代日常分发中的 SFL 1.5、1.6、1.7）；本标准不改变节点主权、身份域或业务语义。

## 1. 目的

把过去“每个任务临时拼一套部署步骤”收敛为一个中立发布内核。小改动只验证、构建、传输和重启它真正影响的部分；核心变更仍进入完整通道。

发布速度来自缩小范围和复用不可变制品，不来自跳过必要验证。

## 2. 分层模型

| 通道 | 判定 | 构建与验证 | 生产动作 |
| --- | --- | --- | --- |
| A0 | 仅内容媒体 | 类型、尺寸、哈希、回读 | 写入内容制品；零服务重启 |
| A1 | 单客户端 | 相关测试、目标类型检查、单客户端构建 | 只移动该客户端指针并只重启目标进程 |
| A2 | 依赖图仅命中一个服务 | 相关测试、服务类型检查、单入口打包 | 只移动该服务指针并只重启目标服务 |
| A3 | 数据库、基础设施、公共依赖、多目标或未知 | 全量 SFL、迁移、契约、回归、完整构建 | 完整候选、迁移、切流、外部验收与回滚 |

未知路径、无法解析的依赖、多个 A2 目标或混合等级一律升级 A3。

## 3. 中立内核与适配器

通用内核只认识：项目、节点、目标、制品、指针、锁、阶段和运输方式。域名、端口、进程、NodeManifest、健康检查与目录全部属于项目适配器。

同一份制品可部署到多个节点；节点选择必须显式给出。L0 与 L1 共享构建结果，但不共享运行目录、服务指针、锁或回滚点。

## 4. 制品协议

制品清单至少包含：

- 源提交与计划摘要；
- 目标和发布等级；
- 目录树摘要、文件数与逻辑字节数；
- 压缩包 SHA-256；
- 关键文件逐项 SHA-256；
- 依赖层身份；
- 删除清单；
- 打包耗时。

远端必须复验压缩包、清单、目录树、关键文件和依赖层。压缩包路径穿越、越界符号链接、作用域不匹配或哈希不一致均不得形成候选。

## 5. 独立运行指针

每个节点目标至少维护：

```text
targets/<target>/candidate
targets/<target>/current
targets/<target>/previous
targets/<target>/releases/<tree-digest>
```

需要 Node 运行依赖的目标额外维护内容寻址的 `runtime` 指针。依赖不随每个代码 release 重复复制；依赖键变化自动升级 A3。

## 6. 事务与回滚

候选验证在切流前完成。生产切流时先记录旧指针和非目标进程 PID，再原子更新目标指针、只重启目标服务并验证健康。失败时恢复旧指针、恢复旧依赖层并重启原服务。

生产总锁、节点锁和目标锁共同生效。冲突应立即返回锁持有者、节点、目标、版本和开始时间。

## 7. 证据与评分

每次运行保存机器可读计划、构建证据、制品清单、部署结果、日志和阶段耗时。95 分只能由真实场景计时得出；本地单元测试通过不等于生产 95 分。

必须覆盖：无改动、A0、A1、A2、候选失败、切流失败自动回滚、L0/L1 双向不干扰和并发抢锁。

## 8. 迁移原则

发布引擎首次上线属于 A3：先安装远端代理和允许清单，建立内容寻址依赖层，给每个现有服务建立独立初始指针，再安装但不自动重启服务定义。完成候选证据后，由 Ethan 单独批准生产切换。

不得借此次迁移修改业务逻辑、数据库语义、Caddy 受保护站点块或域名路由。

## 9. 生产就绪的判定边界

“引擎候选完成”和“某个目标可生产切换”是两个不同结论。目标只有在现网已建立独立初始指针、依赖层、真实服务读取路径、健康探针和回滚基线后，才可将 `productionEnabled` 设为 `true`。

当前尚未完成一次性 A3 接线的媒体、静态登录页、控制台和核心完整发布目标必须关闭式停在候选；不得为了评分绕过现有完整迁移流程。生产 95 分必须由真实服务器候选、切换、隔离与回滚计时共同证明，本地测试不得替代。
