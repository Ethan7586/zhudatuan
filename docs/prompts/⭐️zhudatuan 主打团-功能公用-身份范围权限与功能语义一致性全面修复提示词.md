# **zhudatuan 主打团 · 身份、范围、权限与功能语义一致性全面修复**

> 分类：**功能公用**  
> 用途：当任一业务板块出现身份、Scope、Governance、Permission 或 Capability 结论不一致时，用于取证、修复和双重验证。  
> 使用说明：这是可复用的故障修复模板，不代表已完成的任务需要重复执行。

## 一、锁定原则

1. 身份 Identity、业务范围 Scope、权限 Permission、治理身份 Governance 和功能 Capability 必须强语义一致。
2. 强语义一致不等于代码高度耦合；各模块必须通过稳定契约低耦合协作。
3. 同一个用户、同一个会员关系、同一个组织和同一个 `mall_id`，在所有板块必须得到相同结论。
4. 页面名称不等于运行时边界。必须先查清所有页面实际归属的 API、运行角色和 AccessPipeline。
5. 历史文档、Excel、注释和旧代码属于取证资料，不得覆盖 Ethan 当前确认的决定。

## 二、唯一目标

完整检查并修复 zhudatuan 主打团所有生产板块中的身份链路：

`Session → Principal → Member → Membership → Organization/Mall Scope → Governance → Permission → Capability → Operation`

禁止只修当前报错页面，必须查明同类错误是否存在于其他实际运行边界。

## 三、重点检查

1. 所有 AccessPipeline 创建点。
2. 所有生产数据库运行角色。
3. `current_user` 与 `session_user`。
4. `resolve_session`、`resolve_membership`、`resolve_scope` 和 `resolve_governance` 的参数版本及执行权。
5. Owner、高级管理员、普通管理员和会员在各模块是否被重复解释。
6. Scope Hint、`organization_id` 和 `mall_id` 是否一致。
7. 页面有权限但 API 拒绝，或 API 允许但页面屏蔽的情况。
8. 一个模块故障是否错误阻塞无关模块。
9. 已停用的 `NOLOGIN` 旧角色不得作为生产运行时修复对象。
10. 运行时检查是否验证了真正依赖的契约，而不是无关全局摘要。
11. 验证所有角色能否以真实生产运行角色调用其数据库函数，禁止只检查函数文本、Mock 或权限目录。

## 四、修复要求

1. 建立唯一 GovernanceResolver，所有实际运行时统一接入。
2. 不得硬编码 Ethan、Owner、组织或商城身份。
3. 不得直接修改已登记迁移；数据库变化必须新增受管迁移。
4. 不得手工执行无法重放的生产 GRANT。
5. 不增加未经 Ethan 要求的安全约束、权限收窄、限流或登录门禁。
6. 不修改无关模块，不覆盖其他任务的未提交改动。
7. 外部适配器断线不得拖垮无关业务核心。
8. 配置必须全有或全无；禁止半套配置进入运行状态。
9. 不得以“兼容旧 MVP”为理由重新启用已经退役的运行角色。
10. 未经 Ethan 当前任务明确授权不得部署生产。
11. 管理员邀请必须遵守唯一权限矩阵：Owner 可邀请高级管理员或普通管理员；高级管理员只可邀请普通管理员；普通管理员不可发起邀请。
12. 高级管理员邀请高级管理员必须在写入前返回 403，不得自动降级为普通管理员；任何邀请均不得创建 Owner。
13. Owner 可通过既有所有权转让流程转让 Owner；转让后新身份成为唯一 Owner。
14. 高级管理员没有任何 Owner 转让权限，不得发起、取消、确认或完成 Owner 转让；Owner 转让只能由当前 Owner 操作。

## 五、双重验证

### 第一轮：静态与本地验证

- 每个实际 AccessPipeline 均接入统一 GovernanceResolver。
- 数据库角色与函数执行权矩阵完整。
- 关键数据库边界必须使用真实生产运行角色执行行为测试，不得只用 Mock。
- 定向测试通过。
- 受影响模块 typecheck 通过。
- production build 通过。
- 全量迁移重放通过。

### 第二轮：生产行为验证

- 每个目标服务健康检查为 200。
- Owner 的 Scope 和 Governance 直接从生产数据库验证。
- 以每个真实生产运行角色验证相应函数的 `EXECUTE` 权和内部角色守卫。
- 关键路由未登录返回 401，而不是 404、500 或 502。
- 重复回调、断线和缺失配置不会扩散到无关模块。
- 非目标服务 PID 不变。
- 全部域名发布前后结果一致。
- Caddy 配置无计划外变化。

## 六、必须交付

1. 根因及准确文件、行号和数据库证据。
2. 页面到运行时、运行角色、Scope 和 Capability 的映射矩阵。
3. 修改文件与受管迁移。
4. 测试、构建和生产验证结果。
5. 未完成项及其真实阻塞。
6. 回滚点。
7. 明确回答：这是局部故障、共享契约故障，还是全平台身份体系故障。

## 七、停止条件

- 发现其他任务正在修改目标文件。
- 必须伪造身份、支付或外部配置才能继续。
- 需要重新启用退役角色。
- 需要新增重大业务决策。
- 连续十分钟没有新增证据。
