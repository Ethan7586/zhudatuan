| SDK | `packages/sdk/src/operations/CommerceClient.generated.ts` + 各 domain `.ts` | contractgen 产物 |
| 服务边界 | `services/commerce/src/foundation/application/OperationHandler.ts`、`foundation/interface/OperationController.ts` | contractgen 可重写的 runtime 产物，但业务模块仍有手写输入/响应模型 |
| 数据库 contract catalog | `database/contracts/current.sql` | contractgen 从同一操作定义生成 |
| miniapp | `apps/miniapp/miniprogram/api/{identity,operations}.js`（目录存在时） | 条件生成产物；当前仓库是否有该目录由 generator 动态判定 |
| 平行公共模型 | `packages/api-contract/src/**`、`contract/src/*Contract.ts`、Console 各 `*Schema.ts`、Storefront mapper、Auth `canonicalIdentity.ts` / `canonicalRegistration.ts` | 手写或独立事实；尚未全部由同一源派生 |

因此 `MR-CHECK-CONTRACT` 只能映射 GOV-005 / SRI-007 的“单一源结果”，不能把现有 generator、文件位置或统一 `strictObject` 自动升格为标准。当前 `strictObject` 是共享 helper 的实现事实；未看到逐 operation 的“严格拒绝／兼容扩展”独立声明，所以逐边界兼容策略为 `gap/UNKNOWN`，留给第十五批裁定。
