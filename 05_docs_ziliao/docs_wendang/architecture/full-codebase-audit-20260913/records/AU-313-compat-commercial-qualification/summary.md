# AU-313｜Compatibility 商业资源与员工商品资格

该迁移把品牌、门店、供应商协议、商城品牌授权、商品池、员工标签、城市圈、权益策略和限购模板收敛为服务端资源图。跨租户或不匹配的资源绑定由触发器拒绝；基础表启用 RLS，浏览器角色没有表或资格 RPC 的直接权限。

员工目录在数据库内逐 SKU 评估有效会员、商品状态、商品池、供应商协议、品牌授权、城市圈及权益策略；有适用的 allow 策略时必须匹配，匹配 deny 策略优先拒绝。购物车写入再次评估，结算前对同一用户的 SKU 与 SPU 范围按稳定顺序取得事务 advisory lock，再聚合当次、日、月和累计消费；通过后把策略、城市圈和限购模板证据写入订单。订单创建的请求键也有独立事务锁，确保并发重复请求复用首个响应。

运行入口已确认：员工目录经 `publicRoutes.ts` 调用 `api_catalog_qualified`，购物车经 `cartRoutes.ts` 调用受资格约束的写入 RPC；结算在 AU-302 已审的 cart-checkout RPC 中再次进入 `api_create_order_authorized`。管理员入口在 `adminRouter.ts` 明确注册资格中心、配置、预览、审批、历史、回滚、模拟和员工资格维护；管理端按独立读写权限、数据范围与重新验证状态裁剪调用和返回字段。现有单测覆盖路由 target、权限、范围、敏感员工投影及服务端身份归属；审计工作树缺少 Vitest 依赖，未执行测试。

未发现本模块新增 P0–P3 问题，也未形成删除候选。商业资源与资格函数仍由当前目录、购物车、订单和管理端入口调用，结论为 G0（有真实运行职责）。
