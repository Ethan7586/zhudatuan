# AU-314｜Compatibility 资格中心管理员配置

资格配置写入集中在 `api_apply_qualification_config`。七类配置均先校验服务端传入的活动管理员身份、商城归属、枚举、数量上限、资源归属和变更理由；创建与更新使用版本号进行乐观并发控制。相同配置请求键先取得商城级事务 advisory lock，再复用 24 小时内的同一响应，避免同一管理写入重复执行。

函数把商品池、城市圈、策略、限购、供应商协议、品牌和门店的关联替换放入同一数据库事务；写入后保存前后快照、变更原因、服务器拥有的操作者及授权证据。资格中心读模型也只按当前商城装配配置和选择器数据。该基础写入面仅授予 service role；HTTP 路由在调用前按配置类别应用独立管理权限、管理员 target、商城范围、发布/停用重新验证和请求幂等键要求。后续 AU-315 将单独审计对高影响变更追加的预览、审批与回滚治理层。

已人工审阅 `qualificationAdminRoutes.ts`、`adminRouter.ts` 及其单测：路由已注册；无权限、错误 target、跨商城范围、缺少请求键和缺少重新验证均有明确拒绝路径，响应还按权限在服务端裁剪商业资源、规则、限购与员工选择器数据。审计工作树缺少 Vitest 依赖，未执行测试。

未发现本模块新增 P0–P3 问题，也未形成删除候选；配置函数和路由均由资格中心生产入口使用，结论为 G0（有真实运行职责）。
