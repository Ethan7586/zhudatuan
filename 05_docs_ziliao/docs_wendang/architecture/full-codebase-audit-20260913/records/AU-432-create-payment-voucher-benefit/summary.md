# AU-432｜支付、券与权益初始模型

## 范围与方法

- 主审文件：`02_platform_pingtai/database/supabase/migrations/20260821021000_create_payment_voucher_benefit.sql`。
- 交叉核对：后续支付 outbox、退款恢复、券生命周期和索引迁移，以及 Commerce 的支付、券和权益模块运行链。
- 本批为静态迁移语义与调用关系审阅；未执行数据库重放、构建、测试、支付通道或线上操作。

## 运行结论

支付域建立 intent、attempt、provider observation、capture、payment、退款命令、effect、死信人工复核和恢复案件。订单级幂等键、外部交易/退款号唯一键及 effect 状态为后续异步交付、查询重试和人工恢复提供持久边界；后续迁移与 AU-405—AU-417 已审链路持续使用并扩展它。

券域保存项目/卡池/发放批次/审批、密文券码与指纹、预留、核销、冲正和异常 hold。权益域保存账户、计划、预算、审批发放、不可重复账本 entry 与预留。后续授权解析从项目、券或计划回溯 scope；运行模块将券核销、过期处理和权益读写接入订单/结算流。

## 审计结论

- G0：支付幂等和恢复、券核销及权益账本的基础关系模型，不是删除候选。
- 当前 schema 由大量后续迁移和运行实现共同构成；初始模型不能脱离这些后续约束单独判为缺陷或冗余。
- 支付通道回调、死信恢复与账本余额在本批未做运行验证；保持未验证。
- 本批未新增 P0–P3。
