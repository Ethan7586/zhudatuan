# AU-316｜Compatibility 成员身份保障

成员身份保障独立于业务授权：成员创建及手机号登录别名变更均由触发器维护保障事实；手机号验证缺失时，数据库和 HTTP 两层都会阻止订单创建与内部账户付款。保障中心只通过 service-role RPC 返回掩码手机号、会话和验证状态，原始表及函数不向浏览器角色开放。

当前结算入口 `api_create_order_and_clear_cart_authorized` 在持有订单请求键锁后调用受保障的 `api_create_order_authorized`；后者在资格和订单写入前重验同一成员关系及手机号验证。内部付款同样调用受保障包装器。原始订单与内部付款 RPC 已从 service role 撤销执行权，因此应用服务无法绕开这两层数据库验证。

已人工审阅 `identityAssurance.ts`、订单路由、结算包装器及对应测试。API 在加密地址、库存查询或订单 RPC 前读取保障状态；测试覆盖未验证成员在订单和付款入口被拒绝，以及已验证结算的调用顺序。审计工作树缺少 Vitest 依赖，未执行测试。

未发现本模块新增 P0–P3 问题，也未形成删除候选；身份保障触发器、RPC 和订单/支付调用链均有真实运行职责，结论为 G0。
