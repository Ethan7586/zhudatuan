# 员工端可见与可买资格模型

## 与后台权限的区别

| 问题                           | 系统                 |
| ------------------------------ | -------------------- |
| 谁能编辑商品、订单、会员和财务 | 后台 RBAC + 数据范围 |
| 哪个员工能看见或购买某个 SKU   | 员工资格与商品政策   |
| 客户购买了哪些后台模块         | 套餐能力矩阵         |

三者必须分别判定，菜单隐藏不能代替任何一种服务端控制。

## 建议策略对象

`entitlement_policies`：

- 生效对象：商品池、商品、SKU、城市专区、限售模板。
- 适用成员：组织节点、部门、员工标签、福利计划、白名单或黑名单。
- 条件：城市、时间窗、余额账户、累计数量、购买频次、会员状态。
- 效果：visible、purchasable、quota、price_tier、deny。
- 优先级：明确 deny 优先；更具体资源优先；同级规则按确定性优先级处理。

## 强制执行点

1. 商城目录查询：不可见商品不返回。
2. 商品详情：重新校验可见与可买。
3. 加购物车：校验 SKU、数量、城市和有效期。
4. 结算预览：重新计算资格、价格与额度。
5. 创建订单：事务内最终校验，防止条件竞争和绕过。
6. 售后或补发：根据原订单资格和当前业务政策处理，不直接复用下单判断。

## 隐私与审计

- 员工标签和城市等事实由服务器读取，浏览器只传选择结果。
- 拒绝日志记录政策 ID、资源 ID 和原因码，不记录不必要的敏感标签值。
- 政策版本进入订单证据，确保事后可以解释“当时为什么能买”。
