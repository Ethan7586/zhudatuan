# 备份运行手册

## 触发症状、用户影响与严重级

备份任务失败、PITR 日志间断、对象跨区复制滞后、配置归档签名失败、KMS 元数据缺失或容量达到策略阈值时触发。单次备份失败且仍满足 RPO 为 P1；已越过恢复点、摘要不一致或加密 Key 不可用为 P0。在线交易可继续的前提是当前数据和审计仍安全，不能因备份失败跳过账本、库存、授权或幂等约束。

## Owner 与前置权限

Reliability 主责，Database、Security、Object Storage Owner 协同。操作人需要只读备份目录权限；补跑需要备份服务角色；Key 状态检查需要 KMS 元数据权限，不需要也不得读取密钥值。删除、缩短保留期、解除 WORM 或 Legal Hold 不属于本手册权限。

## 只读诊断

按 `{environment}`、`{recoveryPoint}` 和 `{releaseId}` 查询最近完整备份、连续 WAL、对象版本复制、配置/Manifest 归档、Key 版本元数据及证据归档状态。比较源端与备份端对象数、总字节、首尾时间、SHA-256 清单和签名；检查 90 天容量预测。所有查询只输出标识、状态、时间和摘要，不输出凭据、PII 或对象正文。

## 止血

冻结备份策略变更和生命周期删除；保留失败任务、日志、清单与 Key 元数据。若 PITR 链中断，立即创建新的完整恢复基线并提高日志归档频率；若对象复制滞后，限制低优先级导出和同步，不能删除源版本。Key 不可用时停止产生依赖该 Key 的新备份并升级 Security，禁止改用未审计密钥。

## 恢复

使用受控备份控制器对 `{environment}`、`{recoveryPoint}` 执行幂等补跑。完整备份、WAL、对象版本、配置、Manifest、Key 元数据和证据必须分别成功，再生成统一内容清单并签名。补跑不得覆盖已有同摘要对象；同标识不同摘要必须隔离并触发安全事件。

## 数据核对

校验可恢复时间窗连续、数据库和对象摘要一致、所有归档可解密预检、配置签名绑定同一 releaseId、证据 WORM 生效。每月至少在隔离环境完成一次抽样恢复，执行 Schema Head、角色/RLS、订单金额、库存、支付、账本、凭证、Scope、Outbox/Inbox、报表水位和审计 Hash 链核对。

## 回滚边界

备份是追加事实，不回滚已成功且摘要正确的恢复点。可撤销错误调度或未提交上传；不可原地改写、删除或降低已归档对象的保留与锁。错误清单以新版本冲正并保留旧证据。

## 沟通模板

“备份事件 `{incidentId}`，严重级 `{severity}`，受影响恢复窗 `{from}`—`{to}`，当前在线业务影响 `{impact}`，已采取 `{containment}`，下一核对时间 `{nextCheck}`，负责人 `{owner}`，证据 `{evidenceRef}`。”

## 关闭条件

恢复窗重新连续且满足 RPO；数据库、对象、配置、Key 元数据和证据清单均成功；隔离恢复抽检通过；容量低于告警线并有 90 天余量；告警恢复并记录签字与证据 Hash。

## 复盘链接

P0/P1、重复失败、摘要不一致、Key 不可用或容量预测失准必须建立 `{postmortemUrl}`，记录根因、检测缺口、恢复时间、数据核对、责任人与到期日。
