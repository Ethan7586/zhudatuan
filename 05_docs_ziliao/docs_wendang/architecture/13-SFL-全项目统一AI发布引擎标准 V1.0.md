# SFL 全项目统一 AI 发布引擎标准 V1.0

版本状态：候选标准
适用范围：`zdt-next` 及后续接入同一发布协议的项目
上位约束：SFL 1.8（完整收录并取代日常分发中的 SFL 1.5、1.6、1.7）；本标准不改变节点主权、身份域或业务语义。

## 1. 目的

把过去“每个任务临时拼一套部署步骤”收敛为一个中立发布内核。每项改动只验证、构建、传输和部署它真正影响的目标。

发布速度来自缩小范围和复用不可变制品，不来自跳过必要验证。

## 2. 目标图模型

计划必须直接输出：变更文件、实际受影响目标、必需验证、逐目标制品和部署顺序。

- 工作区依赖变化沿 workspace 依赖图选择消费者；
- 共享服务代码沿生产入口依赖图选择消费者；
- 测试、文档与夹具没有运行目标时只执行直接相关验证；
- 数据库迁移使用独立目标，先于同一提交中的实际服务消费者，且不重启服务；
- 未识别文件选择所有可达真实运行目标作为上界并继续候选流程。

## 3. 中立内核与适配器

通用内核只认识：项目、节点、目标、制品、指针、锁、阶段和运输方式。域名、端口、进程、NodeManifest、健康检查与目录全部属于项目适配器。

同一份制品可部署到多个节点；节点选择必须显式给出。L0 与 L1 共享构建结果，但不共享运行目录、服务指针、锁或回滚点。

## 4. 制品协议

制品清单至少包含：

- 源提交与计划摘要；
- 目标、实际影响和部署顺序；
- 目录树摘要、文件数与逻辑字节数；
- 压缩包 SHA-256；
- 关键文件逐项 SHA-256；
- 依赖层身份；
- 删除清单；
- 打包耗时。

远端必须复验压缩包、清单、目录树、关键文件和依赖层。压缩包路径穿越、越界符号链接、作用域不匹配或哈希不一致均不得形成候选。

## 5. 独立运行指针

每个节点目标至少维护：

```text
targets/<target>/candidate
targets/<target>/current
targets/<target>/previous
targets/<target>/releases/<tree-digest>
```

需要 Node 运行依赖的目标额外维护内容寻址的 `runtime` 指针。依赖不随每个代码 release 重复复制；依赖键变化沿工作区依赖图重新选择消费者。

## 6. 事务与回滚

候选验证在切流前完成。生产切流时先记录旧指针和非目标进程 PID，再原子更新目标指针、只重启目标服务并验证健康。失败时恢复旧指针、恢复旧依赖层并重启原服务。

节点锁和目标锁共同生效，不建立生产全局锁。冲突应立即返回锁持有者、节点、目标、版本和开始时间。

## 7. 证据与评分

每次运行保存机器可读计划、构建证据、制品清单、部署结果、日志和阶段耗时。95 分只能由真实场景计时得出；本地单元测试通过不等于生产 95 分。

必须覆盖：无改动、单目标、多消费者、数据库迁移、验证但不部署、未知文件上界、候选失败、切流失败自动回滚、L0/L1 双向不干扰和并发抢锁。

## 8. 迁移原则

发布引擎首次上线时，先安装远端代理和允许清单，建立内容寻址依赖层，给每个现有服务建立独立初始指针，再安装但不自动重启服务定义。完成候选证据后，由 Ethan 单独批准生产切换。

不得借此次迁移修改业务逻辑、数据库语义、Caddy 受保护站点块或域名路由。

## 9. 生产就绪的判定边界

“引擎候选完成”和“某个目标已生产切换”是两个不同结论。现网独立初始指针、依赖层、真实服务读取路径、健康探针和回滚基线都是结果证据，不是授权等级。

SRI-008 制品来源、SRI-009 目标隔离和 SRI-010 恢复证据只证明结果，不决定放行。除权限池明确裁决外，分支数量、测试数量、历史文档与 AI 风险判断不得阻塞发布。生产 95 分仍必须由真实服务器候选、切换、隔离与回滚计时共同证明，本地测试不得替代。
