# 全代码库系统审计｜11 后续治理路线图

## 执行边界

本路线图不授权在审计分支修改任何实现。每一批都必须从当时最新 `origin/zdt-next` 建立独立小分支，单一目的、定向验证、可回滚；审计、修复、推送、合并和部署仍是不同动作。

## 第一优先级：财务动作凭证的事务消费

- 范围：F-0243 / RV-0025。
- 目的：让每个受 `requiresFinancialActionProof` 约束的财务/发票命令在同一数据库事务内消费 proof，并做版本断言。
- 验证：隔离 PostgreSQL 覆盖有效、伪造、过期、重放、跨 session/resource/request、权限撤销、版本冲突及失败无业务写入。
- 回滚：撤回该单一命令编排提交，保留既有只读审计证据。

## 第二优先级：Auth runtime 与凭据目的地绑定

- 范围：F-0083 / RV-0075。
- 目的：把浏览器加载的 runtime registry 与受信 Manifest/摘要、accounts host 和 API origin 建立不可伪造的同一节点绑定。
- 验证：正确节点通过；“正确 accounts host + 外域 API origin”、摘要不匹配、host 不匹配及陈旧 runtime 均拒绝；不向真实接口提交凭据。
- 回滚：恢复上一份受控 runtime 制品与对应浏览器校验逻辑。

## 第三优先级：发布指针与 Caddy 事实源统一

- 范围：F-0001 / RV-0001，并预先关联 F-0015 的发布门禁问题。
- 目的：确定唯一由正式发布更新、且被 active Caddy 实际读取的 Auth/Console 制品指针，消除 404 的双指针分裂。
- 验证：在隔离/候选节点核对制品 SHA、pointer、Caddy effective config 与 HTTP/SNI 结果；覆盖 200、404、5xx、连接失败和回切。
- 回滚：保留原 pointer 与 Caddy 配置，使用经批准的正式发布控制面回切；不在部署现场准备制品。

## 后续分组

- 启动与健康：F-0249/F-0250 的运行中 drift、contract checksum 与 supervisor 反应，先隔离数据库验证后再决定最小改动。
- 数据与迁移：GX-0045、GX-0047、GX-0048 和全部历史迁移/修复工具，只能在专项隔离环境由数据、身份、发布 Owner 授权复核。
- 质量：补真实运行入口测试，优先 E2E workspace 漂移、生产 Handler/Worker 入口和数据库权限反事实；不能把安装依赖或修绿测试夹带进业务修复。
- 文档与台账：两个无对象标识的 GX 历史计数保持未知，等待原始工作记录；不得为美化统计而删除、降级或虚构候选。
