# SFL 安全与运行完整性标准 v1.0.0

## 1. 唯一职责

本标准定义跨产品可复用的结果保护：身份与疆域不串线；关键写入不重复、不留半套；订单、库存、支付、退款和财务可一致收口；运行制品来源可证明；真实停机后能恢复。

它不定义节点层级和产品业务结果，不登记具体主机、域名、端口、数据库、unit 或制品路径，也不指定必须使用哪种事务、队列、部署器或云产品。

## 2. ZS-0—ZS-4

ZS 是“真实损失等级”，不是任务优先级、验收批次或自动门禁强度。

| 等级 | 损失定义 | 规范后果 |
| --- | --- | --- |
| `ZS-0` | 不能指出可识别的真实损失，只是偏好、命名、数量、耗时或工具选择 | 只能是建议，不得形成强制规则或阻塞 |
| `ZS-1` | 单一用户或单一任务内可逆、可定位、不会污染权威事实的损失 | 可规定结果；实现方式保持可替换 |
| `ZS-2` | 身份串线、越权、跨疆域读写、持久错误绑定或公共契约分叉 | 必须阻止错误结果并保留可判定边界 |
| `ZS-3` | 重复扣款、超卖、漏单、错退款、错账、半套写入或历史交易不可追溯 | 关键写入必须原子、幂等、可追踪并能收口 |
| `ZS-4` | 生产目标错切、共享宿主误伤、运行制品来源不明、数据不可恢复或真实服务长期停机 | 必须有目标隔离、来源证明和经实际恢复验证的恢复路径 |

规则等级由规则登记中的具体损失决定。AI 不得因为“看起来危险”自行提高等级、扩大对象或增加门禁。

## 4. 身份、写入与财务收口

- Credential 只证明认证，不定义节点、权限或资产归属。
- 一次会话只能激活一份 Membership；身份切换后旧权限不继续参与请求。
- “成功”必须由拥有该事实的业务流确认。支付成功不自动等于订单完成、供应商结算或财务结账。
- 四流冲突通过权威查询、明确命令和追加更正收口，禁止覆盖原事实来制造一致。
- 关键写入必须具备可识别业务编号、重复请求识别、允许状态转换、事务／可靠续跑边界和审计关联；技术实现可替换。

## 5. 单一契约源与边界兼容

本标准执行 [`YC-GOV 1.0.0`](01-雍彻科技治理标准.md) 的单一契约源原则。`strictObject` 本身不是缺陷；额外字段应被拒绝还是允许向后兼容，必须由共享契约对该请求或响应边界明确声明。没有声明时不得由前端、后端或测试各自形成长期规则。

本批不修改 `operations.yml`、生成器、Schema、SDK、`canonicalIdentity.ts`、`canonicalRegistration.ts` 或其他契约代码。

## 6. 制品来源、运行一致性与恢复

运行事实至少应能关联：目标疆域／节点、源码版本、不可变制品摘要、配置或清单版本、当前选择点、启动时间、健康结果和恢复点。具体字段存放位置由疆域决定。

“存在备份”“有回滚目录”“服务能重启”都不能单独证明 ZS-4 恢复。恢复证据必须覆盖真实依赖，并证明恢复后目标业务可用且权威数据处于一致状态。无法从控制面证明的部分标为 `UNKNOWN`。

## 7. A0—A3 与授权边界

A0—A3 只能用于当前任务调度、资源取舍或证据组织，不定义 ZS 等级，不决定安全规则是否存在，也不能自动启用或移除门禁。

本版不新增任何“须 Ethan 授权操作”。后续如需增加，必须按 [`YC-GOV §5`](01-雍彻科技治理标准.md) 的完整登记结构，引用 Ethan 的明确决定，精确列出动作和对象并升版本；不得写“所有高风险操作”“涉及生产的一切操作”等开放集合。

## 8. 引用与不越权

- 节点、经营线、Realm、Membership、四流与历史语义来自 [`SFL-CORE 2.2.0`](02-SFL核心标准.md)。
- 具体产品完成态来自对应业务标准；具体域名、服务与恢复对象来自疆域标准及运行注册表。
- 测试和证据只能证明上述结果，不能新增安全规则。
