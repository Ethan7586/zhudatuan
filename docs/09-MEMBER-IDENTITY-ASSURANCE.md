# 会员认证等级与手机验证门禁

## 已实现的认证等级

会员身份、业务权限和身份认证等级是三件独立的事实：

- `Member` 决定“这个人是谁”，后续手机号、微信和企业微信都绑定到同一个会员。
- `Membership + Role + Scope` 决定“这个人能管理或访问什么”。
- `Identity Assurance` 决定“当前身份验证强度够不够执行敏感操作”。

当前有两个认证等级：

| 等级               | 获得方式                       | 可用能力                                 |
| ------------------ | ------------------------------ | ---------------------------------------- |
| 账号认证 `account` | 账号密码注册并登录             | 登录、浏览、收藏、购物车、设备与密码管理 |
| 手机认证 `phone`   | 短信验证码注册、绑定或换绑手机 | 在账号认证能力之上，解锁提交订单和支付   |

## 服务端门禁

“手机未验证不能付款”不是前端按钮规则。订单创建与福利账户付款在三层保持一致：

1. 商城结算页解释限制原因并禁用提交。
2. Commerce API 在读取订单信息、加密收货地址和扣款前校验认证等级。
3. PostgreSQL 授权事务再次校验当前会员与用户关系；原始订单和支付 RPC 不再向应用凭证开放。

因此，篡改页面或直接调用接口也不能绕过手机认证。手机状态缺失时一律按未验证处理。

## 状态提升

`local_phone` 是已通过短信验证的登录别名。手机号注册、首次绑定和换绑成功时，数据库自动把会员提升为 `phone` 等级；删除最后一个手机别名会撤销手机认证。认证状态由数据库返回给商城首页和账号安全中心，不由浏览器自行推断。

短信服务未接入期间：

- 用户名注册用户保持 `account` 等级；
- 安全中心显示“基础会员 · 手机待验证”；
- 绑定入口保留但禁用发送按钮；
- 生产环境不提供固定验证码或模拟放行。

## 后续短信接入

接入真实短信供应商后沿用现有挑战流程：发送验证码、频率限制、短时有效、错误次数限制、一次性消费。验证成功后只需创建或更新同一会员的 `local_phone` 别名，订单和支付能力会自动解锁，不需要迁移账号、会员、余额或订单。
