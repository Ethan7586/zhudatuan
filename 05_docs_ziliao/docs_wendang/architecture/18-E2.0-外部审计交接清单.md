# ERA 2.0 外部审计交接清单

本清单用于把 ERA 2.0（Engineering Readiness & Assurance；技术标识 `E2.0`）交给未参与设计和执行的复核者。它不是认证委托书，也不授权生产实验、权限变更、发布或部署。

## 1. 交接包必须包含

- [ ] E2.0 主标准、机器追踪矩阵及各自 Git SHA、文件 SHA-256。
- [ ] 标准来源登记、检索日期、所用版本、公开/授权访问深度。
- [ ] 被评声明、业务风险、范围边界和 Claim Owner。
- [ ] 适用性与裁剪登记；`NOT APPLICABLE` 必须有理由、批准者和复核触发条件。
- [ ] 执行前形成的 criteria 文件、锁定时间和 SHA-256。
- [ ] 被测 Git SHA、工作树状态、构建/制品 provenance、配置摘要与摘要算法。
- [ ] 环境唯一身份、所有者、拓扑、数据类型、与生产差异清单和时间窗。
- [ ] 精确命令、HTTP/SQL 请求或人工步骤；输入 fixture 和敏感值处理方式。
- [ ] 未经汇总的原始观测、stdout/stderr 或请求/响应、时间戳、文件大小和 SHA-256。
- [ ] 不读取测试程序自报 `PASS` 的独立 oracle、重算命令和重算结果。
- [ ] 异常、偏差、缺失证据、失败重试和对结论的影响。
- [ ] 执行者、设计者、oracle evaluator、复核者的身份、组织和责任关系披露。
- [ ] 复现前置条件、逐步操作、预期原始观测和清理方式。
- [ ] 最终四维结论：声明结论、环境保证、复核保证、对标深度。
- [ ] 评级组合通过 v2 schema 正向校验，且 `MET/NOT MET + NOT ESTABLISHED`、无裁剪引用的 `NOT APPLICABLE`、环境错配和伪独立复核等负向组合均被拒绝。

任一必需材料缺失时，复核者应输出 `UNKNOWN`，不得补写推测值。

## 2. 独立复现顺序

1. 固定仓库提交和 E2.0 profile 版本，先校验所有文件哈希。
2. 阅读适用性、裁剪和禁止声明，不运行任何生产写入或故障注入。
3. 验证 criteria 的时间和哈希早于执行证据；若不能证明，结论为 `UNKNOWN`。
4. 独立建立与声明等级相符的环境，不沿用执行者未记录的隐式配置。
5. 按原输入运行正向和负向用例，原样保存输出，不先看执行者结论。
6. 使用独立 oracle 从原始事实重算；不要读取测试程序的 `PASS` 字段作为依据。
7. 将差异分为判据违反、证据缺失、环境差异和工具差异；分别给出 `NOT MET` 或 `UNKNOWN`。
8. 记录复核者与项目、设计者、执行者的关系，核对 `same_as_executor=false`、`same_as_test_designer=false`、外部性和冲突披露；只有责任独立且材料完整才可写 `INDEPENDENTLY REVIEWED`。

## 3. 各等级的最低补件

| 目标等级 | 最低材料 |
| --- | --- |
| `DEV VERIFIED` | 可重建开发环境、精确输入、原始观测、独立 oracle、Git/config/artifact 摘要 |
| `STAGING VERIFIED` | 上述全部，加稳定 staging 身份、配置管理、生产差异清单、staging 独立数据/凭据和重复执行 |
| `PRODUCTION OBSERVED` | 上述适用材料，加明确生产授权、真实对象和时间窗、变更/影响为零或获授权影响、生产原始收据 |
| `INDEPENDENTLY REVIEWED` | 上述目标环境材料，加外部复核者身份、利益关系披露、独立重算记录和签署日期 |

## 4. E06 当前交接差距

现有 E06 六份 JSON 可支持开发机制层重算，但仍缺：

- 真实 staging 的稳定环境 ID、所有者、凭据/数据边界及与生产差异清单；
- 原执行工作树 clean/dirty 状态、标准化配置清单、完整 stdout/stderr 与退出码；
- 与测试程序实现分离的第二次真实 staging 执行；
- 生产观测授权和生产收据；
- 未参与设计/执行的外部复核者声明和签名。

因此当前对外只能说：**E06 在临时 Docker 开发机制环境达到 `DEV VERIFIED`；真实 staging、生产与独立复核均未建立。**

## 5. 当前禁止交给外部作为结论的声明

- 任何 ISO、IEEE、NIST、OWASP 或 PCI SSC 认证声明。
- ISO/IEC/IEEE 29119 的正式逐条符合性声明，除非提供合法授权全文和逐条适用性记录。
- PCI DSS 合规或正式不适用声明，除非由相应范围责任方完成确认。
- E06 已在真实 staging 或生产通过的声明。
- 以旧 E v1 `PASS` 代替 E2.0 四维结论的报告。

外部复核者可以确认的是证据链、复现结果和本裁剪配置的一致性；是否构成法定、合同或认证意义上的符合性，必须由相应主管方或认证/评估机构另行决定。
