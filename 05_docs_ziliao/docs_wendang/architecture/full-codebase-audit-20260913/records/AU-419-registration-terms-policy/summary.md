# AU-419｜注册条款与成员注册策略

## 范围与方法

- 主审文件：`02_platform_pingtai/database/supabase/migrations/20260820131000_registration_terms_policy.sql`。
- 交叉核对：Commerce 注册/微信注册路由及注册条款策略契约测试。
- 本批为静态调用链与迁移语义审阅；未执行数据库重放、构建或线上操作。

## 运行结论

唯一条款策略行是注册时的权威来源。注册交易以共享锁读取条款版本，只有客户端同意版本与当前版本一致才继续，避免条款更新与接受记录竞态。用户名、手机 OTP 与微信绑定注册均基于有效邀请、员工角色、范围和一次性验证事实创建用户、成员、membership、自身范围及零余额账户；审计记录注册方式和条款版本。

Commerce API 的注册路由直接调用新版 `api_register_storefront_member`、`api_register_username_member`，微信路由调用新版绑定入口；因此该迁移具有实际仓内调用。所有注册入口仅对 service role 开放，契约测试覆盖条款 ACL、签名、版本不匹配和注册情形。

## 审计结论

- G0：条款接受和注册身份落地的实际安全边界，不是删除候选。
- 既有 F-0234（注册/短信/OTP 限额与项目策略冲突）不在本批重复编号；本批未新增 P0–P3。
