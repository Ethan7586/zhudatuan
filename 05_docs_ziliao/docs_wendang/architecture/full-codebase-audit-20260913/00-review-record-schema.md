# 全代码库系统审计｜微观深审记录规范

## 1. 用途与适用范围

本规范把《全代码库微观深审补充协议》转换为可续接、可抽检、可对账的记录结构。它适用于固定基线：

- 基线 SHA：5a1ce71eebbefaa826368a9e1dc17730f9363bc4
- 审计分支：codex/full-codebase-audit-20260913
- 基线文件：4,238
- 人工源码：3,073 个，322,808 物理行
- 人工结构化配置：165 个，78,079 物理行

本规范只定义审计证据和记录方式，不授权修改、删除、修复、推送、合并、部署或改变线上状态。

## 2. 稳定编号

| 对象 | 编号格式 | 示例 |
| --- | --- | --- |
| 审计单元 | AU-三位序号 | AU-001 |
| 检查点 | CP-两位序号 | CP-01 |
| 证据 | E-审计单元-三位序号 | E-AU-001-001 |
| 文件记录 | FILE-五位序号 | FILE-00001 |
| 导出符号 | SYM-文件号-三位序号 | SYM-00001-001 |
| 函数或方法 | FN-文件号-三位序号 | FN-00001-001 |
| API | API-四位序号 | API-0001 |
| 业务不变量 | INV-四位序号 | INV-0001 |
| 状态机 | STATE-四位序号 | STATE-0001 |
| 配置项 | CFG-四位序号 | CFG-0001 |
| 通信关系 | COM-四位序号 | COM-0001 |
| 故障模式 | FM-四位序号 | FM-0001 |
| 问题 | F-四位序号 | F-0001 |
| 垃圾代码候选 | DC-四位序号 | DC-0001 |
| 独立复核 | RV-四位序号 | RV-0001 |

编号一经写入不得复用。结论撤销时保留原编号并标记已撤销，不重新编号造成历史漂移。

## 3. 证据标签

每个重要结论必须在句首使用且只能使用以下标签之一：

| 标签 | 判定标准 | 允许写法 |
| --- | --- | --- |
| FACT | 当前基线代码、配置、数据库只读结果或运行结果直接证明 | [FACT][E-AU-001-001] 路由在 X 文件 Y 行注册 |
| INFERENCE | 两个或更多已登记事实共同支持，但代码没有直接声明结论 | [INFERENCE][E-...][E-...] 该服务是当前唯一写入者 |
| HYPOTHESIS | 有明确验证方法的待测假设 | [HYPOTHESIS] 该超时可能造成重复写入；需执行指定夹具 |
| UNKNOWN | 当前证据不足，且不能安全推导 | [UNKNOWN] 线上是否仍有外部消费者未取得证据 |
| CONFLICT | 两个来源对同一当前事实给出互斥答案 | [CONFLICT][E-...][E-...] 文档与发布清单对当前运行单元描述相反 |
| STALE | 有证据证明描述曾经成立，但在当前基线已经失效 | [STALE][E-历史][E-当前] 旧工作区名称已不存在 |

规则：

1. 重要结论至少引用一个证据编号。
2. INFERENCE 必须列出推导链，不得只写“综合判断”。
3. HYPOTHESIS 必须记录可执行验证方法和预期结果集合。
4. UNKNOWN 必须记录缺失证据、取得方式和阻塞边界。
5. CONFLICT 不得私自选择更方便的来源；保留双方证据。
6. STALE 必须同时有历史成立证据和当前失效证据。
7. 删除、废弃、无调用者、无运行职责、权限无效、数据库对象无用、迁移失效、兼容消费者消失等结论，至少需要两类相互独立的证据。

## 4. 独立证据分类

每条证据记录以下字段：

| 字段 | 内容 |
| --- | --- |
| 证据编号 | 稳定 E 编号 |
| 证据类别 | 静态引用、动态注册、构建配置、路由清单、包导出、运行日志、生产只读观察、Git 历史、数据库依赖、测试行为、部署清单、外部使用记录之一 |
| 基线 | 代码证据固定写基线 SHA；运行证据写观察时点和目标版本 |
| 来源 | 文件路径与精确行、命令、只读查询或运行入口 |
| 观察 | 最小必要输出，不复制无关日志 |
| 解释 | 该证据直接证明什么，不证明什么 |
| 可复核方法 | 另一审计者如何重复取得 |
| 敏感性 | 是否包含凭据、个人信息或生产标识；报告不得复制不必要敏感值 |

独立性规则：

- 两次文本检索属于同一“静态引用”证据类别，不构成两类证据。
- 一个源文件和它生成的文件通常属于同一生成链，除非独立运行验证证明输出被实际加载。
- 文档与注释只能作为线索或历史证据，不能单独证明当前运行职责。
- 测试只能证明测试入口观察到的行为，不能自动证明生产路由、生产配置或生产制品已启用。
- 构建成功只能证明制品可构建，不能证明线上正在运行。

## 5. 文件级审计记录

每个人工源码文件必须恰好有一条 FILE 记录。人工结构化配置、自动生成文件、构建产物和归档也必须有覆盖记录，但可使用对应专项模板。

### 5.1 FILE 记录必填字段

| 序号 | 字段 | 记录要求 |
| ---: | --- | --- |
| 1 | 存在理由 | 当前业务或平台职责，不能复述文件名 |
| 2 | 创建或加载者 | import、dynamic import、框架发现、进程、脚本或人工流程 |
| 3 | 加载条件 | 路由、环境、权限、节点、构建目标、命令或测试条件 |
| 4 | 导出内容 | 链接到全部 SYM 记录；无导出也要写“无” |
| 5 | 导出消费者 | 直接、间接和外部消费者；区分生产与测试 |
| 6 | 输入 | 参数、请求、环境、文件、数据库结果、事件 |
| 7 | 输出 | 返回值、响应、文件、数据库状态、事件、日志 |
| 8 | 状态读写 | 内存、浏览器、文件、缓存、全局或进程状态 |
| 9 | 数据库读写 | 数据库、schema、表、函数及读写类型 |
| 10 | 网络调用 | 协议、目标、超时、重试和取消 |
| 11 | 事件 | 生产、消费、消息版本及提交时点 |
| 12 | 环境变量 | 链接到 CFG 记录 |
| 13 | 用户权限依赖 | 身份、角色、能力、作用域和 Access Version |
| 14 | 运行环境依赖 | 节点、进程、浏览器、Node、Worker、systemd 或 CI |
| 15 | 初始化副作用 | 构造或启动阶段副作用 |
| 16 | 模块加载副作用 | 顶层执行、注册、连接、Timer、日志和全局修改 |
| 17 | 注册职责 | 路由、服务、任务、Handler、插件或队列注册 |
| 18 | 测试/生产差异 | mock、条件编译、环境分支和入口差异 |
| 19 | 资源释放 | 连接、句柄、Timer、Listener、AbortController、临时文件 |
| 20 | 失败恢复 | 重试、回滚、清理、补偿、恢复入口 |
| 21 | 对应测试 | 测试文件和测试用例编号 |
| 22 | 测试可信度 | 测试是否通过真实职责入口、反事实破坏是否会失败 |
| 23 | 对应文档 | 当前文档、契约、runbook、事故记录 |
| 24 | 文档准确性 | FACT、STALE、CONFLICT 或 UNKNOWN，并附证据 |
| 25 | 兼容职责 | 旧路径、旧字段、旧 API、回滚或外部消费者 |
| 26 | 等价/重复实现 | 候选实现及行为差异 |
| 27 | 可否独立删除 | 只能写 G0、G1、G2、G3 或 GX；G3 需独立复核 |
| 28 | 删除首个失败点 | 最可能首先失败的入口、构建、契约、数据或运维流程 |
| 29 | 最终结论与置信度 | 证据标签、结论、置信度和未确认项 |

### 5.2 文件记录附加字段

- 文件编号、路径、所属模块、文件类型。
- 基线 blob SHA。
- 物理行数。
- 审阅范围：完整文件或大文件逻辑区间。
- 审阅者、日期、审计单元和检查点。
- 风险等级。
- 是否需要第二轮复核。
- 详细记录文件路径。
- 覆盖清单同步状态。

### 5.3 大文件规则

- 不得只读文件开头。
- 先登记逻辑区域、起止行和区域职责。
- 每个区域分别记录输入、输出、副作用、错误路径和消费者。
- 所有区域完成后才能把文件状态改为“已深入审阅”。
- 任何未读区域必须保持 UNKNOWN，并使文件状态保持“暂未审阅”或“需要专项专家复核”。

## 6. 导出符号记录

对默认导出、命名导出、类型、常量、函数、类、Schema、路由、Handler、Repository、Adapter、Worker、配置、公共 CSS 类、数据库函数、Shell 函数和工作流输出建立 SYM 记录。

| 序号 | 字段 | 记录要求 |
| ---: | --- | --- |
| 1 | 符号名称 | 含 default、匿名导出的稳定描述 |
| 2 | 声明位置 | 文件与精确行 |
| 3 | 直接消费者 | 静态 import、调用或加载者 |
| 4 | 间接消费者 | 包入口、路由、框架、生成器、脚本链 |
| 5 | 重新导出 | package export、barrel 或兼容转发 |
| 6 | 动态访问 | 字符串、反射、配置、文件发现、插件 |
| 7 | 仅测试使用 | 是/否/未知，列出测试 |
| 8 | 公共契约 | API、事件、类型、CSS、数据库或脚本接口 |
| 9 | 运行时副作用 | 加载或调用副作用 |
| 10 | 可见范围 | 当前范围及是否有证据支持缩小 |
| 11 | 兼容导出 | 当前、历史、疑似无效或未知 |
| 12 | 删除/改名影响 | 首个失败点、验证和恢复方法 |

“零静态消费者”必须继续检查框架发现、动态加载、插件、路由、Worker、外部包、数据库、Shell、GitHub Actions、生成器、测试夹具和历史回滚。

## 7. 函数与方法记录

业务关键函数、公共函数、异步函数、数据库函数和部署函数必须建立 FN 记录。

| 序号 | 字段 | 记录要求 |
| ---: | --- | --- |
| 1 | 唯一职责 | 用可观察结果描述 |
| 2 | 参数来源 | 调用方、请求、配置、数据库或事件 |
| 3 | 运行时校验 | Schema、手工校验或缺失 |
| 4 | 类型真实性 | TypeScript 类型与运行数据是否一致 |
| 5 | 默认值 | 默认值及业务依据 |
| 6 | 特殊输入 | null、undefined、空串、零、false、空数组 |
| 7 | 参数变异 | 是否修改传入对象或集合 |
| 8 | 外部可变状态 | 全局、缓存、数据库、环境、时钟 |
| 9 | 调用顺序依赖 | 隐含时序和前置步骤 |
| 10 | 隐藏前置条件 | 类型系统未表达的不变量 |
| 11 | 不变量 | 链接 INV 记录 |
| 12 | 返回路径 | 正常、空、提前返回 |
| 13 | 抛错路径 | 错误类型、错误码和 cause |
| 14 | 提前返回 | 条件和副作用状态 |
| 15 | 外部调用 | 网络、文件、进程、服务 |
| 16 | 数据库写入 | 事务、表、行锁、约束 |
| 17 | 日志 | 级别、上下文、敏感数据和重复打印 |
| 18 | 权限判断 | 身份、作用域、能力和数据库执行身份 |
| 19 | 重试 | 层级、次数、退避和幂等 |
| 20 | 超时 | 超时来源及是否取消底层工作 |
| 21 | 资源清理 | finally、dispose、close、abort |
| 22 | Promise | await、明确放弃或可能悬空 |
| 23 | 并发安全 | 竞态、锁、版本、CAS、唯一约束 |
| 24 | 重复调用 | 幂等键和结果一致性 |
| 25 | 半完成状态 | 中途失败后的数据库和外部状态 |
| 26 | 已测分支 | 测试用例编号 |
| 27 | 未测分支 | 条件、错误、并发、恢复 |
| 28 | 复杂度 | 分支、职责和理解成本 |
| 29 | 拆分判断 | 仅报告，不在审计分支实施 |
| 30 | 相邻重复 | 等价函数、差异和统一风险 |

TypeScript/JavaScript 函数还要记录 any、unknown 转换、断言、非空断言、可选链、null/undefined、枚举完整性、Schema 重复、对象覆盖、浅拷贝、安全整数、金额、时区、序列化、Promise.all、AbortSignal、ESM/CommonJS 和 Node/浏览器边界。

## 8. 条件分支与状态机记录

每个关键 if、条件表达式、switch、权限分支和状态流转至少记录：

- 条件原文与位置。
- true、false、未知输入结果。
- null、undefined、空串、零和 false 语义。
- 可达性。
- 默认分支。
- 静默失败或失败后继续执行。
- 资源清理和状态恢复。
- 跨模块状态一致性。
- 对应测试与未测组合。

状态表固定字段：

| 当前状态 | 允许操作 | 下一状态 | 拒绝条件 | 数据写入 | 事件 | 失败结果 | 重试结果 | 并发冲突结果 | 回滚方式 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

枚举增加新状态时，必须核对所有 switch 和默认分支；不能用 default 掩盖漏项。

## 9. React 页面与组件记录

每个页面和关键组件在 FILE/FN/SYM 记录之外，补充：

- 路由注册、懒加载、刷新、深链、参数编码、404、无权限和登录回调。
- 本地状态、URL 状态、服务端状态和真实所有者。
- 用户、作用域和 Access Version 切换后的缓存隔离。
- Hook 顺序、Effect 依赖、清理、Strict Mode、取消、Timer、Listener、陈旧闭包和竞态。
- React Query key、分页、enabled、staleTime、重试、Mutation 失效、乐观回滚和 AbortSignal。
- 表单校验、重复提交、busy、回车、自动填充、Unicode、手机号、金额、日期和错误焦点。
- CSS 直接导入、全局导入、@import、构建收集、选择器消费者、层叠顺序、响应式、弹窗、空态、错误态、主题、打印与真实页面对照。
- 可访问性语义、Label、键盘、焦点、Dialog、Escape、ARIA、动态通知、对比度、表格、滚动和触控区。

CSS 删除候选必须同时拥有入口/构建证据、选择器消费者证据和真实页面视觉对照；缺一项不得标 G3。

## 10. API 记录

每个真实注册 API 建立 API 记录：

| 字段 | 内容 |
| --- | --- |
| 方法与路径 | 含版本和 host 条件 |
| 注册位置 | 路由、Controller、中间件顺序 |
| 调用者 | 前端、服务、Webhook、外部消费者或未知 |
| 身份与权限 | 身份来源、作用域、对象级授权、数据库执行身份 |
| 请求 | content-type、大小限制、路径/query/body Schema 与交叉校验 |
| 响应 | 成功 Schema、状态码、流或文件 |
| 错误 | 错误码、HTTP 映射、内部信息泄露 |
| 幂等与分页 | key、结果语义、cursor/offset |
| 超时/重试/取消 | 每层策略和放大风险 |
| 数据写入 | 事务、表、事件和审计日志 |
| 外部副作用 | 支付、短信、OSS、供应商、邮件等 |
| 版本兼容 | 旧路径、字段、消费者和下线依据 |
| 可观测性 | request id、trace、日志、指标 |
| 测试 | 是否走真实路由注册入口及反事实可信度 |

API 专项必须检查重复注册、中间件顺序、可信身份、scope 来源、对象级越权、请求限制、客户端断开、连接释放、优雅关闭、Readiness/Liveness 和内部 API 暴露。

## 11. 业务不变量记录

每个核心域建立 INV 表：

| 字段 | 内容 |
| --- | --- |
| 不变量 | 从真实业务代码和契约归纳，不预设 |
| 业务依据 | 当前产品决定、契约或可观察行为 |
| 代码执行点 | 文件、函数与行 |
| 数据库执行点 | 约束、函数、触发器、RLS |
| API 校验点 | 路由/Handler |
| 测试 | 正常、失败、并发和恢复 |
| 并发成立性 | 锁、唯一性、版本或未知 |
| 恢复成立性 | 重试、补偿和回滚后 |
| 文档差异 | FACT、CONFLICT、STALE 或 UNKNOWN |
| 破坏检测/修复 | 指标、查询、告警和人工恢复 |

支付终态、退款上限、借贷平衡、事件单次生效、幂等、角色冲突、商品删除、库存、会话绑定和权限版本只作为检查方向，必须由当前代码证据确认。

## 12. 数据库与迁移记录

每个人工迁移建立独立记录，至少包含：

- 创建、修改、删除的对象。
- 事务、锁、全表重写、默认值和索引影响。
- 数据回填、进度、中断、续跑和重复执行。
- 失败残留、新旧代码兼容与回滚。
- Owner、Grant、Revoke、Execute、RLS、SECURITY DEFINER 和固定 search_path。
- 真实调用者、索引对应查询、NULL 唯一性、外键删除。
- 时间、金额、精度和时区。
- 迁移制品、ledger、顺序和执行数据库身份。

必须建立六个矩阵：

1. 表所有权矩阵。
2. 函数所有权矩阵。
3. RLS 策略矩阵。
4. 数据库角色矩阵。
5. 服务账户访问矩阵。
6. 迁移执行身份矩阵。

任何数据库权限删除均标 GX，进入独立专项，不进入普通垃圾清理。

## 13. 异步、队列和 Worker 时序记录

每条关键链路记录：任务创建、持久化、事务提交、发布、Worker 领取、租约、去重、外部调用、结果写回、确认、重试、死信、人工重放、积压指标和告警。

每条链路必须只读推演：

- 写入前崩溃。
- 写入后、确认前崩溃。
- 外部成功、结果落库前崩溃。
- 取得任务锁后崩溃。
- 旧进程未退出时发布新版本。
- 数据库不可用。
- 重复投递。
- 消息乱序。
- 时钟漂移。
- 多 Worker 竞争。
- 新旧消息/代码版本并存。
- Poison Message 和死信恢复。

推演只形成分析与测试建议，不在生产制造故障。

## 22. 自检、抽检和独立复核

### 22.1 模块关闭前反向自检

任何高风险疑问都使结论降为 UNKNOWN、G1、G2 或 GX。

### 22.2 随机抽检

- 普通模块：至少重新核查 5% 已审文件，向上取整且至少 1 个。
- 高风险模块：至少 15%，向上取整。
- P0、P1、G3、GX：100% 独立复核。
- 抽检重新从入口追踪，不对照原报告直接复述。
- 发现明显遗漏即扩大抽检；系统性遗漏则重审整个模块。

RV 记录包含抽检文件、原结论、复核结论、一致性、遗漏类型和扩大范围。
