# 第四批｜契约重建过渡与运行收口

状态：`TRANSITION`。来源是 Ethan 在 2026-09-12 当前任务中的明确决定；本文件记录过渡边界和运行事实，不自称新契约池标准。

## 1. 当前决定

1. 契约池将成为契约架构、契约库与整体代码结构之间唯一的公共接口。
2. 唯一接口不等于唯一实例；契约池可以有主池、备选池、灾备池和不可变稳定快照，但同一命名空间与版本不得形成多重事实。
3. 代码、Session、服务和 Worker 不得自行创造公共契约、局部 Schema 权威、兼容规则、默认回退或私有判断。
4. 新契约池必须在整体架构完成后统一设计和安装；第四批只清除旧权威、建立过渡标识并收口实际运行版本。

## 2. 过渡期运行规则

- 旧 `x-contract-version`、旧 checksum、旧操作／事件目录可以作为遥测数据保留，但不能拒绝请求、阻止 Worker 启动或把服务判定为不可用。
- 数据库可写性、现行 schema、Realm／Membership／Scope、专用数据库角色、业务关系、关键表与真实外部依赖继续按其本来职责工作；它们不能被冒充成旧契约。
- 缺少新契约池裁决时，执行者只能记录 `UNKNOWN` 并回报，不得在局部补一份长期事实源。
- 每份新制品必须记录源码 SHA、制品摘要及本过渡模式；生产运行实例必须能追到该制品。

```text
node / realm
```
