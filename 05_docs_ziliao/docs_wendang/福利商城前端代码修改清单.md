## 1. 关键结论与 P0/P1

### 1.1 总结

当前主要问题不是缺少若干前端依赖，而是以下边界同时断裂：

1. 当前六端和多个共享包没有可审计 Git 基线。
2. Requirement 生成链仍绑定旧工作簿。
3. Contract 有 Operation 元数据但没有请求和响应 Schema。
4. SDK 允许调用方通过泛型自行宣称响应类型。
5. Scope 未完整进入 URL、RequestContext 和 Query Key。
6. Console、Storefront 和 Miniapp 在浏览器或小程序端聚合跨领域业务真相。
7. 高风险动作没有固定 Preview 到 Receipt 状态机。
8. Store 将最终核销离线排队并可能显示伪成功。
9. Storefront 同时存在 Next、Vinext、Cloudflare、RSC、Worker、手写 Router 和 OSS 部署。
10. 296 条需求没有真实 Evidence，六端测试和部署证据不足。

### 1.2 P0

| 编号 | 当前问题 | 关键代码证据 | 必须修改 |
|---|---|---|---|
| P0-0 | 无可审计基线 | 六端及多个共享包整体未跟踪，旧应用大量删除 | 首先建立内容寻址 Manifest、Git 基线、签名 Release 和回滚点 |

1. 全部 Web Client 切换 React Router Data Mode。

8. 建立 Testing Library、MSW、Playwright、axe 和 Storybook。
9. 补 5000 商品、请求取消、Scope 竞态、Web Vitals、Bundle Budget 和真实发布证据。
10. 按工作簿补齐 Store、Supplier、Storefront、Miniapp 中缺失的专业旅程。

### ADR-FE-001：Web 运行时

### ADR-FE-002：Storefront

Storefront 唯一采用标准 Vite SPA。

必须删除：

- next
- vinext
- @cloudflare/vite-plugin
- @cloudflare/workers-types
- @vitejs/plugin-rsc
- react-server-dom-webpack
- wrangler
- next-env.d.ts
- next.config.ts
- pages 入口
- StorefrontWorker
- dist/client 特判
- .next、.open-next、.wrangler 审计豁免

目标制品：

~~~text
apps/storefront/dist/
  index.html
  assets/
~~~

### ADR-FE-003：Router 与 Query 分工

- Router 负责 URL、Scope、loader、action、pending、NotFound、Denied、error boundary 和焦点恢复。
- Loader 只解析 URL，并通过 QueryClient.ensureQueryData 预热，不维护第二份数据缓存。
- TanStack Query 唯一拥有服务端状态、取消、失效和重读。
- 低风险写可以使用 Route action 或 Feature mutation。
- 高风险写固定由 Feature 状态机驱动，不塞入通用 route action。

### ADR-FE-004：Miniapp

Miniapp 保持微信原生，不引入 React、Taro 或 uni-app。

共享的不是 React 组件，而是生成的：

- Operation
- Request/Response Schema
- Error Contract
- Experience Schema
- DeepLink Schema
- VI Token
- Brand Asset

### ADR-FE-005：前后端边界

禁止：

- UI 直接 fetch。
- 公开 call 泛型。
- 未校验 unknown 响应。
- 浏览器 BFF。
- 全局可变 Scope。
- 浏览器跨领域聚合。
- 前端计算权限、资格、价格、库存、退款、结算和账务。
- 最终支付、核销、退款、结算离线排队。

## 6. 全部路由与 Feature 数据流

### 6.1 统一读流程

~~~mermaid
sequenceDiagram
    actor U as 用户
    participant R as Data Router
    participant Z as URL Schema
    participant Q as TanStack Query
    participant S as Named SDK
    participant A as Operation API
    participant V as Response Schema
    participant UI as Feature UI

    U->>R: 点击/深链/前进后退
    R->>Z: 解析 Scope、筛选、分页、详情
    Z-->>R: Typed Route Input
    R->>Q: ensureQueryData Query Key
    Q->>S: namedMethod + RequestContext + signal
    S->>A: Operation Request
    A-->>S: unknown JSON 或 Error Contract
    S->>V: parse
    V-->>S: Typed DTO
    S-->>Q: Typed Result
    Q-->>UI: Resource State
    UI-->>U: 渲染与焦点恢复
~~~

Scope 或路由变化：

1. Router 生成新 URL。
2. 旧 Query 收到 AbortSignal。
3. FetchTransport 真正终止网络。
4. Query Key 因 scopeKind、scopeId、accessVersion 变化。
5. Response Guard 拒绝旧 generation 的结果提交。

sequenceDiagram

    participant X as Execute
    participant Q as Reread

### 7.4 状态

~~~text
Loading
Empty
Ready
Refreshing
Stale
Denied
NotFound
Conflict
RateLimited
Offline
Failure

~~~

规则：

- Ready 且后台请求中为 Refreshing。
- 超过 staleTime 但仍可展示为 Stale。
- Error code 决定错误类型，禁止正则猜 message。
- RateLimited 展示 retryAfter。
- Conflict 展示当前服务端版本并要求重新 Preview。
- Offline 对支付、核销、退款、结算只允许失败。
- Retry 是明确动作，不能无限自动重试。

### 7.5 5000 商品

- 服务端分页、筛选、排序。
- 浏览器不加载全部商品。
- 默认页大小 50，最大值由 Contract 固定。
- 批量动作先创建 Filter Snapshot。
- 命令只携带 snapshotId 和少量 include/exclude。
- 切换筛选、分页或 Scope 必须取消旧请求。
- Table 先使用正常分页；只有渲染行数实测超预算时才懒加载 Virtual。

翼码

动态标题：

- 立即隔离新写入口。
- 保留安全只读能力。
