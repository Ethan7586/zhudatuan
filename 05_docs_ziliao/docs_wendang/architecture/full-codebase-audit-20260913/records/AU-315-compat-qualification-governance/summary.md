# AU-315｜Compatibility 资格变更治理与员工事实

高影响资格变更先在数据库计算预计受影响的员工和 SKU；停用既有规则、激活城市/限购规则、全量或 deny 权益规则、50+ SKU 商品池及 100+ 员工影响均进入审批队列。队列以商城、配置对象、版本与请求键限定，申请写入预览、原始配置、理由和审计事实。

审批 RPC 在锁定请求后重新验证独立 `qualification.approve` 权限、管理员身份和拒绝覆盖；申请人本人不能审批。审批前再次比对对象版本，变更已过期则标记 stale；通过才调用 AU-314 的配置写入 RPC，保留审批意见、授权证据和结果。历史读取由审计快照生成，回滚只能从同商城同对象的历史快照取得配置，并重新走常规权限、重新验证、预览和必要审批路径。

员工资格事实（城市、状态、属性、人工标签）也有商城内在职 storefront 成员校验、版本冲突检测、标签来源保护和审计快照。治理中心及模拟、审批、历史、回滚和员工维护 API 均由 `adminRouter.ts` 注册；响应按员工读取、配置管理和审批权限分别裁剪，前端提交的操作者身份不会传入 RPC。

已人工审阅 `qualificationGovernanceRoutes.ts`、关联测试和数据库调用链；测试覆盖员工数据脱敏、审批重新验证、服务器操作者身份、人工标签输入及模拟范围。审计工作树缺少 Vitest 依赖，未执行测试。

未发现本模块新增 P0–P3 问题，也未形成删除候选；治理表、RPC 与管理入口均有真实运行职责，结论为 G0。
