# AU-407｜内部支付意图与统一出站事件

## 范围与方法

- 主审文件：`02_platform_pingtai/database/supabase/migrations/20260820127100_payment_domain_outbox.sql`。
- 交叉核对：支付中继 `20260820127200_payment_domain_relay.sql`、支付效果处理器契约测试及后续微信支付观察迁移。
- 本批为静态调用链与迁移语义审阅；未执行数据库重放、构建或线上操作。

## 运行结论

迁移把微信专用出站表提升为带 `wechat` 与 `internal` 来源的统一 `payment_outbox`，并保留来源、主题、支付锚点和不可变信封之间的约束。订单级内部付款被建模为不可变 `payment_intent`；支付明细仍保留福利/餐补两种原始记账及退款路由身份。

订单从待付款完整转为已付款时，`order_internal_payment_outbox` 触发器会核验支付方式数额、统一幂等根键、账户分配和账本证据，再写支付意图并产生内部捕获事件。它先用订单咨询锁序列化聚合版本；后续中继受租约、来源和状态证据约束地领取事件，契约测试覆盖事件扇出、账目平衡、履约与通知效果。

支付意图、出站表和内部验证函数均不向直接客户端或服务角色开放；实际工作通过受限 RPC 完成。

## 审计结论

- G0：该迁移是内部支付由同步状态转向可靠事件驱动效果的实际桥梁，不是删除候选。
- 本批未新增 P0、P1、P2 或 P3；未运行验证均已明确保留为未验证状态。
