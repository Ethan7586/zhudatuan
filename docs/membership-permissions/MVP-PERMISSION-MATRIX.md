# MVP 权限矩阵

## 默认角色

| 角色              | 默认范围         | 主要能力                                       | 明确不包含                     |
| ----------------- | ---------------- | ---------------------------------------------- | ------------------------------ |
| 买家/员工         | 本人             | 浏览商品、创建订单、查看本人订单、维护本人账号 | 他人订单、后台管理、财务       |
| 商家/供应商操作员 | 商城/供应商      | 商品、库存、订单、发货                         | 成本价以外的财务、会员授权     |
| 运营              | 商城             | 商品运营、订单、售后、统计、审计查看           | 支付密钥、角色授权、Owner      |
| 客服              | 商城             | 订单与售后查询、客服会话处理                   | 改价、退款执行、财务、角色授权 |
| 财务              | 集团/商城/供应商 | 财务查看、对账、结算、发票                     | 商品发布、会员授权             |
| 企业管理员        | 集团 + 指定商城  | 会员、组织、商城、业务查看                     | Owner、平台租户、接口密钥      |
| 平台运营          | 平台             | 跨下属层级运营和安全治理                       | Owner 转移                     |
| Owner             | 平台             | 唯一最高级控制权                               | 不能通过日常后台复制或修改     |

## 核心原则

- 角色只有允许项；个别例外用会员级明确禁止处理。
- 默认拒绝，没有权限代码就不能调用接口。
- 数据范围不能由浏览器传入决定，目标资源范围必须从数据库加载。
- 导出、成本价、手机号、支付、退款、作废、提现、接口密钥必须独立授权。
- 同一人不应同时拥有申请和审批同一笔高风险业务的能力。
