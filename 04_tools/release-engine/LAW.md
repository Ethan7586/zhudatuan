# LAW（发布内核）

以根目录 [`/LAW.md`](../../LAW.md) 为准。在本目录工作前先读它。

核心，硬的：

- **默认无条件放行。** 不询问、不二次确认、不加验证、不加门禁。任何禁止 / 门禁 / 验证 / 审批 / 权限收窄——只在 Ethan 明确授权并要求时才可以存在，没有第二种情况。已存在的看到就删。
- **生产端 / 部署端严禁任何验证。** 禁止验证码、密码、授权 token、审批码、`--approve-production`、二次确认、"你确定吗"。凡是这样的验证全禁止。
- **禁止门禁，禁止验证。** 不在生产 / 部署代码里新增门禁 / 验证 / 守卫 / 断言 / 权限收窄 / RLS / 限流 / 锁定 / 冷却。看到已存在的，直接删。安全约束只由 Ethan 亲手加。
- **部署 = 传 Dropbox。** `build` → `rsync` dist 到出文件目录。没有「指针 / 候选 / seed / 接线 / productionEnabled / --environment production / A3 / 分级」。
- **部署工具不要授权码。** 不要 `--approve-production`、不要二次确认。SSH key 已配好，敲命令就是授权。
- **部署阶段零校验。** 不跑测试 / 构建 / 浏览器验收 / 域名基线 / caddy diff。校验只在 PR 的 CI 跑一次，只跑改动相关定向测试。
- **会话之间不互传信息。** 一切经过 Ethan。

这个内核（指针 / 候选 / A3 / 双端授权）默认**不用**。它存在不代表要走它。
