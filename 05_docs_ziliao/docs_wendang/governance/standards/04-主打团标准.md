# 主打团标准 v1.0.0

## 1. 唯一职责

本标准定义主打团作为 SFL 具体产品必须产生的业务结果：商城、会员、邀请、开店、供应链、商品、购物车、订单、履约、支付、退款、售后和财务。实现可以更换框架、服务边界、表结构和发布方式，只要结果与权威事实不变。

节点、经营线、Realm、Membership、主权／承载和四流共同语义由 [`SFL-CORE 2.2.0`](02-SFL核心标准.md) 定义；安全与运行结果由 [`SFL-SRI 1.0.0`](03-SFL安全与运行完整性标准.md) 定义。本标准不得改写它们。

## 2. 业务结果

### 2.1 商城、会员、邀请与开店

- 每个可经营商城有唯一 `mall_id`，能判定经营节点、经营状态、可售范围和交易归属。
- 会员在目标 Realm 和节点形成独立 Membership；可查看和操作的本人权益、订单与资料不能串到其他 Membership。
- 邀请必须有可判定的邀请人 Membership、目标经营线、状态和使用结果；成功注册后的父级与级号遵守 SFL，不另建平行邀请树。
- 无邀请注册、有效邀请递进、L11 边界和同凭据多 Realm 身份结果以 SFL-CORE 为准。
- 开店升级原节点经营能力，形成 `mall_id` 和必要经营配置；不清空会员身份、邀请血缘和历史交易。

### 2.2 供应链、商品与购物车

- 供应商主体、当前商城的供应关系、合同、商品范围、履约、结算和发票责任可分别判定；同一供应商服务多个商城时不得合并范围。
- 商品与 SKU 有可识别状态、价格、库存与供应来源；结算使用被确认的商品版本和数量。
- 购物车表达当前 Membership 在当前商城的购买意图；进入结算时重新取得权威商品、价格、库存和资格结果，客户端缓存不能直接成为成交事实。

### 2.3 订单、履约与支付

- 结算形成一个可追踪主订单，并按供应商、合同、履约与结算责任形成商品行和供应商经济腿。
- 库存预占、释放、扣减与回补和订单生命周期一致；失败或取消不能留下无归属占用。
- 履约记录实际负责主体、商品行、发货／收货／退货状态和可追踪凭据；一个供应商异常不自动逆转其他合法经济腿。
- 支付意图绑定唯一订单、金额、币种、经营商城和支付渠道尝试；已确认成功不被后到超时或非终态结果降级。
- 渠道收款成功只证明现金流结果，不冒充订单完成、供应商结算、发票或财务结账。

### 2.4 退款、售后与财务

- 退款绑定原支付、原订单、选中商品行、金额与原因；重复通知或重试不产生第二次退款。
- 售后按原商品行和供应商经济腿推进退货、退款、库存回补与财务冲销；无法原路执行时进入显式异常处理。
- 财务记录应收、实收、供应商应付、退款、分配、结算、凭证与对账差异；只有财务流拥有会计账本语义。
- 订单、商品、现金与财务不一致时保留各自原始事实，通过对账追加纠正，不覆盖历史制造假一致。

## 4. 验收解释

验收只测量上述业务结果和真实损失，不规定必须使用某个脚本、测试框架、表名或证据包。页面存在、接口返回 200、测试绿色或某张表有记录都不能单独代替端到端业务结果。

公共请求和响应语义遵守 [`YC-GOV 1.0.0`](01-雍彻科技治理标准.md) 的单一契约源原则。本批只确立原则，不改变当前冻结中的契约实现。

## 5. 非职责

品牌视觉细节、具体页面布局、公司经营主体、支付商户资料、域名、端口、数据库、systemd 与 Caddy 均不在本标准写死。已确认的疆域事实应进入具体疆域文件；尚未确认的业务政策保持 `UNKNOWN`。
