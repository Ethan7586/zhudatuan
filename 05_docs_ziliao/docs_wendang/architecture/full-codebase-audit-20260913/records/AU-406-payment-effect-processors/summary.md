# AU-406｜支付效果处理器基础

## 范围与方法

- 主审文件：`02_platform_pingtai/database/supabase/migrations/20260820127000_payment_effect_processors.sql`。
- 交叉核对：后续支付中继 `20260820127200_payment_domain_relay.sql`、效果执行器 `20260820127300_payment_domain_effects.sql`、退款闭环和支付效果契约测试。
- 本批为静态调用链与迁移语义审阅；未执行数据库重放、构建或线上操作。

## 运行结论

该迁移将支付效果的旧投递概念改为本地可完成事实，并建立三类下游事实：不可变且借贷平衡的财务分录、按来源效果幂等的履约订单/明细、以及按来源效果和收件人去重的通知派发。效果记录增加租约令牌、到期时间、死信与结果码；状态约束禁止处理态缺少租约，负载也有大小上限。

后续支付中继以 `payment_outbox` 的租约和 inbox 去重建立效果，效果执行器再用本迁移定义的表与状态完成财务、履约和通知工作。所有表及内部平衡函数均启用或保留最小权限，撤销公共、匿名、已认证和服务角色的直接表访问；真正执行入口由后续受限服务角色 RPC 提供。后续退款闭环扩展同一财务和通知边界，说明这些表仍承担真实运行责任。

## 审计结论

- G0：该迁移是支付效果、财务、履约与通知的持久化和完整性基础，不是删除候选。
- 本批未新增 P0、P1、P2 或 P3；未运行验证均已明确保留为未验证状态。
