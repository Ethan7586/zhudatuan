# AU-437｜领域数据回填

## 范围与方法

- 主审文件：`02_platform_pingtai/database/supabase/migrations/20260821026000_backfill_domain_data.sql`（724 行）。
- 交叉核对：迁移执行/契约脚本、后续领域数据对账迁移及已审的各领域基础模型。
- 本批为静态迁移语义审阅；未重放数据库、读取生产数据、构建或测试。

## 运行结论

该单事务迁移将 legacy `public.*` 数据迁入组织、身份、成员、权限、合作方、目录、定价、资质、库存、购物车、订单、履约、通知、支付、权益、财务、券、runtime、审计、报告和风控领域表。它保留历史事件、幂等键、死信、回调、状态、金额和审计投影，而非仅搬迁当前活跃业务数据。

迁移在分销商联系方式、微信身份、合作方地址和券码等敏感数据进入目标表前设置安全阶段断言；对固定基线记录采用 `not exists`/冲突处理以避免部分重复导入。后续 `reconcile_domain_data` 对数量、金额、引用和哈希进行对账，数据库契约脚本将本文件作为固定迁移序列的一部分。

## 审计结论

- GX：一次性全域历史数据迁移和兼容责任。不是运行垃圾，禁止删除、修改或在现场重放；任何变更须先做独立数据迁移设计、备份/恢复演练和第二轮复核。
- 静态审阅未发现 P0–P3；是否可在目标历史数据上完整通过只能由受控迁移演练与后续对账证明，本批保持未验证。
