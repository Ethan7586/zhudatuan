## 对齐原则

1. 没有真实损失或只对应 `ZS-0` 的检查只能建议／报告，不能阻塞。
2. 测试和脚本不能创造标准；找不到标准规则 ID 的机器门禁标为 `overreach` 或 `unknown`，不自行合理化。
3. 同一真实损失应有一个清晰执行点；平行重复实现登记为 `duplicate`，但不得在取证阶段直接删除。
4. A0—A3 只能作为调度参考，不得决定保留或删除安全控制。
5. 单一契约源对齐必须指出当前公共请求／响应、Schema、类型和 SDK 的各事实源；本批不擅自选定生成器。
6. `strictObject` 的严格或兼容扩展结论必须来自共享契约逐边界声明，不能由检查器统一推断。
7. 动态调用、生产启用状态或控制面无法证明时标 `UNKNOWN`。
