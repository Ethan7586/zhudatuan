# 商业资源与员工资格系统实施说明

状态：第二阶段配置闭环已落地，尚未部署生产。

需求来源：项目归档的《20260709 福利商城功能清单》中“已选/组合/待选商品池”“城市专区”“限售模板”，以及既有会员权限边界模型。

## 一、已落地的系统边界

### 商业资源关系

- `brands`、`stores`：品牌与线上/线下门店主体。
- `supplier_brand_bindings`：供应商经营、拥有或分销哪些品牌。
- `brand_store_bindings`：品牌与直营网点、授权店、加盟店的关系。
- `mall_supplier_agreements`：商城与供应商的供货、结算和有效期协议。
- `mall_brand_authorizations`：商城可销售品牌的显式授权。
- `store_org_unit_bindings`：门店为哪些组织节点提供履约、核销或服务。
- `catalog_pools`：上游来源池、商城已选池、组合池。
- `catalog_pool_items`、`mall_catalog_pool_bindings`：SKU 入池及商城选池关系。

所有重复保存 `tenant_id` 的关系表都由触发器校验引用对象租户，跨租户拼接会被数据库拒绝。

### 员工资格事实

- `employee_qualification_profiles`：员工城市和可扩展属性。
- `employee_qualification_tags`：有有效期的员工标签。
- 企业、部门、用户和会员事实继续从现有真实表读取；部门规则包含子部门。

### 可见与可买策略

- `entitlement_policies`：策略头、动作、效果、优先级、有效期和版本。
- `entitlement_policy_subjects`：全部、企业、部门、用户、会员或标签。
- `entitlement_policy_resources`：全部、商品池、SPU、SKU 或城市专区。

判定规则：

1. 商业资源未入有效商品池或缺有效供货协议，直接不可见、不可买。
2. 配置品牌后必须同时存在供应商经营关系与商城品牌授权。
3. 城市专区可以分别约束“目录可见”和“收货城市可买”。
4. 明确 `deny` 优先于 `allow`。
5. 某资源只要配置了生效中的 `allow`，员工必须至少命中一条；未配置策略时保持现有商品兼容。

### 限售模板

- 支持按 SKU 或 SPU 汇总。
- 支持单次、自然日、自然月、生命周期的数量和金额上限。
- 日/月边界使用 `Asia/Shanghai` 业务时区。
- 下单时按“用户 + SKU”获取事务锁，防止并发请求同时穿透限额。
- 同一订单中的多个 SKU 如果属于同一个 SPU，会合并计算单次限售。

## 二、强制执行点

| 阶段            | 服务端行为                                                      |
| --------------- | --------------------------------------------------------------- |
| 商品目录        | `/api/v1/products` 必须登录；数据库只返回 `visible=true` 的商品 |
| 商品展示        | 返回 `purchasable` 与原因码；不可买商品仍可用于解释展示         |
| 购物车读取      | 重新判定；失效商品自动取消选择                                  |
| 加入/修改购物车 | 数据库重新校验可买、城市事实与限售                              |
| 创建订单        | 在事务和锁内最终校验；拒绝前端绕过与并发超买                    |
| 订单证据        | 保存策略版本、策略 ID、城市专区 ID 和限售模板 ID                |

目录判断使用员工档案城市；订单最终判断使用收货城市，浏览器不能上传员工标签或部门事实。

## 三、后台入口

“商业资源与员工资格中心”已经支持真实读取与配置：

- 商城供应商协议、供应商品牌关系、商城品牌授权、品牌商品和品牌门店关系。
- 商城精选/组合商品池与 SKU 入池。
- 城市专区及其城市、SPU/SKU 范围。
- 可见/可买的允许或明确拒绝策略，适用对象支持集团、部门、员工、会员身份和资格标签。
- SKU/SPU 的数量与金额限售模板。

所有保存都必须填写变更原因；草稿不影响员工端，发布和停用需要 15 分钟内的二次身份验证。写入使用幂等键和版本号，重复提交不会重复写，旧页面覆盖新版本会被拒绝。每次成功变更都会写入操作者、授权依据、变更前后内容、原因、请求标识和客户端信息。

读取响应也按服务端权限裁剪：没有商业资源、资格或限售读取/管理权限时，不返回对应数据；员工与会员选择器只向规则管理员开放，前端隐藏不作为安全边界。

## 四、向后兼容

迁移会为现有商城创建一个“已选商品池”，把现有 SKU 入池，并为当前商品关系补齐商城供应商协议。因此迁移本身不会让现有商品因新关系模型突然消失。

未配置城市、资格和限售策略时，现有有效商品保持可见、可买。新增配置只会收紧明确绑定的资源。

## 五、后续增强

1. 发布前预览影响人数、双人审批和历史版本一键回滚。
2. 策略模拟器：输入会员、SKU、城市、数量，返回完整判定路径。
3. HR 同步员工城市与标签；城市代码接入标准行政区划。
4. 高并发下限售计数专项压测与订单取消额度释放规则。
