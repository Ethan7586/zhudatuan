### 1.1 阻断上线的问题

1. `NodeContext` 有 `access_version`，但仓库当前实现和迁移均没有 `lineage_digest`，因此
   SFL-01、SFL-34 直接失败。
2. 活跃合同／Console 仍有固定 `scopeKinds`，AutoNode 仍保留 legacy request 与
   `LEGACY_DIRECT` 路径，因此 SFL-23、SFL-33 失败。
3. 没有可验收的 Cross-Node Grant 与授权型跨节点 Worker；现有 Domain Binding Set 只有
   `candidate / active / rolled_back`，没有标准要求的 `primary / draining / retired`，因此
   SFL-27—SFL-30 失败。
4. 第十批机器矩阵没有逐操作的 `request_schema_ref / response_schema_ref / scope_resolver_ref`
   等 D05 必需字段；真实执行内核测试虽通过，SFL-D05 仍失败。
5. 本地 production build 未通过：auth/console 缺必需构建环境，storefront 的复用依赖缺
   `@tailwindcss/postcss`，commerce 的复用依赖缺 `exceljs` 且另有既存 Node Buffer 类型错误。
   CI 必须真实执行受影响构建，不能以规划器跳过代替通过。

## 3. 真实业务结果

### 3.1 节点、会员、Scope 与升级

- Hosted 节点：L1/L5/L6/L11，唯一父边、关系版本、原子回滚、基础设施调用 0。
- NodeContext/Scope：主权 L0/L1、Hosted L1/L5/L6/L11、当前关系、祖先／后代／子树闭包均通过；
  `lineage_digest` 缺失。
- 注册：L0/L3/L5 无邀请均生成直属 L6；L6—L10 邀请依次生成 L7—L11；L11 不生成 L12；
  跨线邀请拒绝且零残留。
- 同凭据多 Realm：A=L6、B=L8，Membership、账号、父链、Scope、会话与生命周期独立，五路并发收口。
- Hosted 开店：L3/L6/L8/L11 的 node/realm/parent/level/lineage 不变，只增加商城能力和同事务 Outbox。
- Sovereign 升级：L2/L5/L8 保持身份与血缘，生成版本化 domain/resource/manifest，四步状态机、三类故障恢复、
  五路幂等、竞争与回滚通过。

### 3.2 多供应商四流

在全新 PostgreSQL 17 应用 285 个迁移后执行：

- 3 个商品行形成 3 个独立供应商经济腿；商品额 3000、折扣 200、订单／支付分配 2800。
- 正向生成 12 条供应商财务事实；部分与全额售后生成 8 条财务冲销事实。
- 路径保留 `L0,L1,L-2,L2,L6,L7`，逆向严格按 `6,5,4,3,2,1` 回放。
- 关系和合同换版后，历史商品行仍指向成交时供应商、合同与责任方。
- 同一现有并发重放 SQL 启动 5 个真实 PostgreSQL 会话后全部成功；最终仍只有 1 个订单、1 个供应商腿、
  1 个退款分配、1 个库存恢复和 4 个财务冲销事实。
