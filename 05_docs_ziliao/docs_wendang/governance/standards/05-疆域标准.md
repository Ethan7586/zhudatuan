# 疆域标准 v1.0.0

## 1. 唯一职责

疆域标准把通用 SFL 标准绑定到一个具体项目或节点。它只回答“这里实际是谁、在哪里、引用哪版标准、有哪些本地适配和已知例外”，不得反向修改 SFL 通用语义，也不得从域名、代码名称或部署位置推断经营主体、支付资料、品牌政策或所有权。

## 2. 证据等级

疆域事实必须逐项注明来源与观察时间：

| 证据状态 | 含义 |
| --- | --- |
| `CONFIRMED` | Ethan 当前明确确认，或权威控制面／权威数据源直接证明 |
| `DECLARED` | 版本库或配置文件声明了该值，但未证明当前运行控制面一致 |
| `OBSERVED` | 在标明时间直接观察到运行结果，但不承诺永久有效 |
| `UNKNOWN` | 无直接证据、来源冲突或尚未查询；不得推断 |

代码、文件名和域名能证明“存在这样的声明”，不能自动证明经营主体、产权、支付商户或当前生产状态。

## 3. 疆域文件必备内容

每个具体疆域使用 [`疆域标准模板`](realms/TEMPLATE.md)，至少声明：

1. 自己的 `realm_standard_id / 中文名称 / version / status / scope / effective_at / supersedes / authority / responsibility / explicit_non_responsibilities`；
2. 精确引用 `YC-GOV / SFL-CORE / SFL-SRI` 版本；属于特定产品时再引用业务标准版本；
3. `realm_id / mall_id / operating_line_id / operating_node_id / participant_realm_id / participant_membership_id` 的已知值或 `UNKNOWN`；
4. 身份入口、应用入口、域名、服务、数据边界、运行位置、恢复对象和本地适配；
5. 每个事实的证据状态、来源和观察时间；
6. 与通用标准不同的限期兼容项、真实损失、Owner 和退出条件。

## 5. 运行注册表边界

[`SFL 运行注册表`](SFL-运行注册表.md) 只记录可变事实，状态永远不能作为 `ACTIVE` 标准登记。它可以被更新而不提升 SFL 或疆域标准版本；事实无法由控制面证明时必须写 `UNKNOWN`。
