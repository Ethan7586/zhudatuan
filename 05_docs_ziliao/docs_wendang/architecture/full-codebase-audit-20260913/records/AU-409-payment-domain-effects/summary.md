# AU-409｜支付域效果执行器

## 范围与方法

- 主审文件：`02_platform_pingtai/database/supabase/migrations/20260820127300_payment_domain_effects.sql`。
- 交叉核对：出站中继迁移、支付效果处理器/退款超越/恢复契约测试，以及 Commerce `PaymentJobs` 运行实现。
- 本批为静态调用链与迁移语义审阅；未执行数据库重放、构建或线上操作。

## 运行结论

该迁移将付款捕获事实按固定顺序拆为会计、履约和通知效果。会计效果先重新验证付款、订单、微信观察或内部付款意图，再写不可变且平衡的分录；履约效果要求已提交库存预留和已付款子订单，按来源效果幂等写履约单及行项目；通知效果仅在付款证据一致时写待派发通知。退款已完全覆盖捕获的情形会使履约和通知效果安全地终止为 superseded。

效果领取和执行均以订单咨询锁、短期租约、顺序阻塞、退避重试、十二次死信及审计记录控制。契约测试覆盖过期租约拒绝、分录平衡及不可变性、幂等、死信阻塞/人工忽略后的恢复和最小 ACL。

与 AU-408 相同，固定基线未发现实际 Commerce 作业调用 canonical 效果领取/执行 RPC；当前作业呈现另一套 `payment` 与 `runtime.outbox` 模型。因此整条 canonical relay/effect 链进入 DC-0063/G1，不能据此删除。
