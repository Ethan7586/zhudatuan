# AU-417｜支付死信受权恢复

## 范围与方法

- 主审文件：`02_platform_pingtai/database/supabase/migrations/20260820129100_payment_deadletter_recovery.sql`。
- 交叉核对：支付死信告警表、支付效果和微信查询状态机、恢复契约测试。
- 本批为静态调用链与迁移语义审阅；未执行数据库重放、构建或线上操作。

## 运行结论

该迁移提供范围受限的告警查询和重放接口。重放先验证成员锚点、权限、授权证据、租户/企业/商场范围及不可变请求幂等，再按订单锁恢复 payment effect 或支付查询到待处理状态；随后写不可变恢复请求、关闭关联告警并留下审计记录。直接客户端权限被撤销，仅 service role 可执行。

固定基线未找到这两个精确管理 RPC 的仓内调用。告警、恢复请求和底层死信对象仍承担运行恢复职责，因此静态未接线不能作为退役结论。

## 审计结论

- DC-0068 / G1：不得删除；先核验生产告警看板、service-role 调用、恢复日志与人工演练。
- 本批未新增 P0、P1、P2 或 P3；未运行验证均已明确保留为未验证状态。
