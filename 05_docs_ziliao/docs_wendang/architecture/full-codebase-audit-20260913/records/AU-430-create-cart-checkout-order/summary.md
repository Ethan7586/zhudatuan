# AU-430｜购物车、结算与订单初始模型

## 范围与方法

- 主审文件：`02_platform_pingtai/database/supabase/migrations/20260821019000_create_cart_checkout_order.sql`。
- 交叉核对：后续回填、对账、索引和范围解析迁移，以及 Commerce 的订单创建、支付、退款、售后和 Console 订单读取链。
- 本批为静态迁移语义与调用关系审阅；未执行数据库重放、构建、测试或线上操作。

## 运行结论

购物车域以局部唯一索引确保成员、商城、应用组合最多一个 active cart，并以 `(cart_id, listing_id)` 固定购物项覆盖边界。结算域保存加密收件信息、地址/区域 token、带过期时间的会话和价格、库存、履约、资质等证据哈希。

订单域以 `checkout_id` 唯一约束防止同一结算会话重复建单；订单行保存标题和单价快照，订单状态按支付、履约、售后和生命周期四个维度拆分。售后复核动作记录授权证据和 trace，状态事件以订单内 sequence 固化审计顺序。

后续迁移回填并对账旧数据、补充按状态和时间的索引，范围解析从 cart、checkout 与 order 反查授权域。订单创建、支付结算、退款和售后实现持续读写这些表，且 Console 订单界面消费同一状态模型。

## 审计结论

- G0：购物车、加密结算地址、报价证据和订单/售后审计的基础关系模型，不是删除候选。
- 地址密文与 token 的实际密钥边界、结算超时回收和跨进程幂等性需要以对应运行链专项验证；本批未执行验证，未将其写成已证实缺陷。
- 本批未新增 P0–P3。
