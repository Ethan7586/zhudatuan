# 统一前端体验与性能标准 v1.0.0

本文件是已完成代表页面验证的 v1.0.0 定稿候选和迁移依据。它已获得 Ethan 建立标准的明确决定，但在根 [`LAW.md`](../../../../LAW.md) 精确登记前保持 `REFERENCE`，不得冒充已启用标准或阻塞生产部署。

## 1. 目标

新页面不再依赖事后逐页救火。Console、商城/H5、登录和客服页面共同继承稳定框架、局部加载、请求优先级、状态保留和诚实反馈；各产品只在业务密度、移动端交互和数据来源上做必要适配。

## 2. 体验预算

所有时间从用户动作或导航开始计算，并分别记录冷启动与热启动。单次截图、单次开发机结果或测试通过不能代替真实 P75 数据。

| 指标 | v1.0 目标 | 用户结果 |
| --- | ---: | --- |
| 点击或触控反馈 | `≤ 100ms` | 用户立即知道动作已被接收 |
| 已进入应用后的稳定页面外壳 | `≤ 200ms` | 标题、导航和主要操作不消失 |
| 热启动可操作 | `≤ 300ms` | 返回页面或相邻标签接近即时切换 |
| 冷启动首屏主数据 | `≤ 500ms` 目标，`> 1000ms` 必须专项分析 | 首屏不被次要统计和大列表拖住 |
| INP | P75 `≤ 200ms` | 连续操作没有明显阻塞 |
| 页面切换 CLS | `≤ 0.05`，稳定外壳不得主动位移 | 页面不晃动、不缩放、不失去定位 |

测量必须注明：页面、构建 SHA、设备档位、网络条件、缓存状态和样本时间。性能证据用于校准标准，不自动创造部署门禁。

## 3. 页面结构

1. 同一业务中心的品牌、标题、主导航和标签栏属于稳定外壳；内部切换只替换内容区。
2. 已挂载外壳内禁止回退成整页通用加载画面。
3. 加载骨架必须与目标内容的主要尺寸和分区一致，避免数据到达后的二次跳变。
4. 同一中心的相邻标签共享代码时应形成一个工作区模块；确需拆包时，在空闲、悬停、聚焦或指针按下阶段预载下一跳。
5. 图片必须声明固有宽高；首屏关键图片预解码，非首屏图片延迟加载。

### 3.1 直线视觉语言

1. 页面结构统一使用直线和直角：卡片、面板、导航选中态、步骤框、输入控件、按钮、骨架与强调边线不得绕圆角。
2. 禁止用圆弧装饰线、圆角边框或胶囊形容器表达层级；层级使用直线、留白、色块和边框粗细表达。
3. 头像、状态点、进度环等本身具有圆形语义的元素可以保留圆形，但必须显式标记为语义圆形，不得借此恢复结构圆角。
4. 新页面从设计系统继承直线几何；存量页面在改造时消除局部硬编码圆角。
5. 直线不等于扁平：层级和交互使用克制的边框变色、轻阴影、色块与短促过渡表达；不得用位移或放大制造晃动。

## 4. 数据与渲染

1. 首屏只等待主数据链；统计、历史、帮助信息和非当前标签数据延后。
2. 相同 Scope、权限版本和查询条件复用同一缓存，不重复发起等价请求。
3. 导航离开时取消无价值的旧请求；返回时优先显示仍然可信的旧数据并后台刷新。
4. 大列表使用服务端分页、窗口化或渐进渲染；首屏不得同时创建与解码整批不可见图片。
5. 次要预加载不得与当前页面主请求争抢连接、CPU 或解码资源。

## 5. 状态连续性与反馈

1. 标签切换保留各自的滚动位置、展开项、筛选草稿和已加载内容，除非业务明确要求清空。
2. 程序性标题聚焦使用 `preventScroll`，不得改变用户视觉位置。
3. “正在切换”等状态使用稳定尺寸的状态槽，不临时插入并推动布局。
4. 加载文案说明正在等待的对象：页面代码、主数据、后台同步或生产状态，不使用无法定位原因的笼统文字。
5. 未接入遥测时不得显示“服务运行正常”；构建 SHA、产品版本和数据版本必须使用不同名称。

## 6. 分端适配

| 前端 | 在统一标准之上的重点 |
| --- | --- |
| Console | 高密度数据、键盘操作、稳定工作区和批量任务 |
| 商城/H5 | 移动端首屏、商品图片、触控反馈和购买主链 |
| 登录 | 最少网络往返、快速恢复会话和安全反馈 |
| 客服 | 会话连续性、消息增量与滚动锚点 |

## 8. 代表页面验证

验证环境均为 2026-09-14 生产页面、真实会话、无人工网络限速；结果用于校准规则，不替代持续 P75 观测。

| 代表类型 | 页面与版本证据 | 验证结果 | v1.0 结论 |
| --- | --- | --- | --- |
| 多标签业务中心 | Console 工程中心；`98382e47`、`46e0827b` | 标题、品牌和标签形成稳定外壳；内部切换不再整页卸载；直线结构以边框变色和轻阴影保留层次 | UIX-001、UIX-004、UIX-005、UIX-009 可作为同类中心的迁移基线 |
| 数据密集列表 | Console 选品中心；生产 SHA `cd69031ce53998df6dac8ca503e72212fd662bcb` | 生产重载 61 个请求，页面切换 CLS `0.00`；选品代码块约 14KB，主接口约 539ms，剩余主要耗时在后端响应 | 前端拆包和首屏优先级方案成立；接口仍按 `≤500ms` 预算继续压缩 |
| 移动端商城首屏 | `hbbtzn.com`；生产制品来自 `cd69031ce53998df6dac8ca503e72212fd662bcb` | 390×844 移动视口下约 40 个请求；不再下载约 98KB 的桌面框架；移动框架约 12KB；首批 100 商品接口约 509ms，后续 500 商品在空闲时分批补齐；CLS `0.0154` | UIX-003、UIX-005、UIX-006 的分端加载与渐进数据规则成立；首批接口仍需继续优化 |

三类代表页面均已覆盖。验证同时证明：统一规则能够减少前端重复工作，但不会掩盖后端接口超过预算的事实。

## 9. 定稿与启用边界

1. v1.0.0 内容定稿条件已经完成，本文件可以作为后续页面改造的统一候选基线。
2. `REFERENCE` 不等于 `ACTIVE`；只有 Ethan 明确决定启用，并由根 `LAW.md` 精确登记后，本标准才产生项目级约束力。
3. 启用前不得用本文件阻断部署；启用后也不得把性能检查塞进“部署”原子口令。
4. 全站存量页面迁移属于下一轮工作，应按页面族分批实施并保留真实测量结果。
