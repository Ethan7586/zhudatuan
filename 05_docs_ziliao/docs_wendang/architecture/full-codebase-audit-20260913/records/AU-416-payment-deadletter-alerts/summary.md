# AU-416｜支付死信告警

## 范围与方法

- 主审文件：`02_platform_pingtai/database/supabase/migrations/20260820129000_payment_deadletter_alerts.sql`。
- 交叉核对：支付效果、微信查询死信状态机及后续恢复迁移。
- 本批为静态调用链与迁移语义审阅；未执行数据库重放、构建或线上操作。

## 运行结论

迁移把支付效果和微信支付查询的死信状态变化转换为持久化 critical 告警，而非仅写日志。触发器仅在首次进入死信时建立或重新打开告警；资源类型与标识唯一，保留错误码、尝试次数、订单范围和发生次数。既有死信被一次性回填。

告警与恢复请求表都启用 RLS，直接访问被撤销；恢复请求不可修改或删除。后续恢复迁移以这些表承接受权人工操作，因此这不是孤立告警表。

## 审计结论

- G0：死信发现和恢复流程的持久化边界，不是删除候选。
- 本批未新增 P0、P1、P2 或 P3；未运行验证均已明确保留为未验证状态。
