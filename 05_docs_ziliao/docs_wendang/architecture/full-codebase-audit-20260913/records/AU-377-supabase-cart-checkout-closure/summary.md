# AU-377｜Supabase 购物车结算闭环

`20260815010000_cart_checkout_closure.sql` 是早期 Storefront 购物车读模型与“建单后清空同批购物车项”事务封装。购物车快照按 tenant、mall、user 取数，并为每个 SKU 调用资格判定；创建订单包装器按商城和幂等键串行化，先调用受授权建单，再在同一数据库事务中删除实际下单 SKU，对重复请求返回原建单结果并声明未再次删除购物车项。

`commerce-api` 的实际入口已核实：购物车 GET 需要 `order.create` 并传入服务器认证范围；建单路由先完成订单权限、手机认证、请求幂等、输入解析和收货信息加密，随后才调用该数据库入口。因数据库函数在一个事务内运行，建单后购物车删除失败会连同建单回滚。

该初版建单包装器已被 `20260820125000_atomic_checkout_inventory.sql` 显式删除并替换为 `api_checkout_order_authorized`；购物车快照也在后续 taxonomy 与库存单一事实源迁移中重定义。它不是当前 checkout 实现，却是有顺序依赖的迁移历史和演进证据，归 G0，不能仅凭当前签名已替换而删除。

未发现新增 P0–P3 或删除候选；未执行订单、库存、测试或数据库写入。
