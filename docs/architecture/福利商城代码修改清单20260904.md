## 0. 执行结论

本次不是重建新项目。`zhudatuan` 已有 32 个模块、276 个 Operation、103 个事件、三个生产客户端、11 个一期渠道扩展、统一请求管道、Outbox/Inbox、可靠任务和较完整的质量门，应继续作为唯一主线。代码改造集中在六件事：

1. 新增 `approval` 第 33 个模块，把卡券、财务、退款、发布和风险例外的审批语义收敛到同一领域。
2. 将 `zhudatuan_li` 独有的 97 个 Operation 做语义融合。其中 40 个映射到主线已有或更强 Operation，57 个新版卡券 Operation 纳入新的 Voucher 模型；不复制旧 Runtime、旧 API 版本或兼容层。
3. 把主线三个客户端补为六个：保留 `auth`、`console`、`storefront`，迁入 `miniapp`，新增 `store` 和 `supplier`。
4. 保留 `zhudatuan_li` 智慧翼视觉与完整多端体验，把原型、Demo、Mock 和本地预览转成唯一 Design System 与真实业务 Operation；验证完成后删除原型运行时代码。
5. 补齐商品、订单、财务、权限、装修和六类导入的真实闭环，生产界面不再存在“只预览、已载入、即将开放、无行为按钮”。
6. 通过追加迁移、回填、核对、冻结、硬切和删除完成数据演进；不修改 316 个历史迁移，不双写，不保留长期兼容。

## 1. 不可协商的代码规则

### 1.1 依赖方向

```text
客户端 View → ViewModel → Application → Public Port ← Infrastructure → 生成 SDK

后端 Interface → Application → Domain
                         ↓
                        Port ← Infrastructure

跨模块：Application → other/public Facade
异步：Domain Event → Outbox → Integration Event → Inbox → Consumer
```

- Domain 禁止导入 HTTP、数据库、React、生成 DTO、队列和其他模块。
- Application 禁止直接 SQL、直接 Provider、直接发布消息和读取他域表。
- Interface 只做合同解析、上下文建立、调用和响应映射。
- Infrastructure 实现 Port，不决定业务状态。
- 客户端 View 禁止导入 SDK/Gateway/Router；Route 禁止直接调用 SDK。
- 其他模块只允许导入 `modules/<name>/public`。

### 1.2 命名

- 生产目录：小写单词，如 `approval`、`credential`、`importing`。
- 生产文件：PascalCase 单一职责，如 `CreateIssueOrder.ts`、`CredentialPool.ts`。
- 禁止：`New`、`Old`、`Final`、`V2`、`Copy`、`Temp`、`Helper`、`Helpers`、`Utils`、`Common`、`Misc`、`Manager`。
- Operation/Event 使用点分层级；数据库、迁移、SQL、测试、脚本和配置按生态允许下划线或短横线。
- 移动后不保留 `index` 之外的转发兼容文件；完成同一 PR 后旧路径必须消失。

### 1.3 状态和配置唯一源

| 事实 | 只允许修改 | 禁止新增 |
| --- | --- | --- |
| Operation | `packages/contract/definitions/operations.yml` | 页面路径常量、私有 DTO、手写 SDK 方法 |
| Event | `packages/contract/definitions/events.yml` | 模块私有 Integration Envelope |
| Error | `packages/contract/definitions/errors.yml` | 用户可见 `new Error(string)` |
| Permission | `packages/contract/definitions/permissions.yml` | 页面权限数组 |
| Capability | `packages/contract/definitions/capabilities.yml` | Feature 私有开关 |
| Route/Navigation | `config/navigation.yml` | 另一个侧栏配置或孤儿路由 |
| Provider | `config/providers.yml` + Extension Manifest | 中央 Provider `if/else` |
| Runtime Config | `config/*.yml` + `packages/config` | 页面内默认环境值 |
| UI Token | `packages/design/src/tokens.json` | 散落十六进制颜色、私有圆角/阴影 |
| 中文状态/错误 | `packages/presentation` | 各页面独立翻译 switch |
| MVP | `docs/福利商城功能清单.xlsx` | 手写第二份状态清单 |

### 1.4 硬切规则

- 先 Add/Modify 新实现，再 Backfill/Verify，再冻结旧写入并切换，最后 Delete。
- 不向最终客户端公开 `/v2`、`legacy`、`compat`、`old` 路由。
- 不双写旧/新卡券表；切换点之前回填，切换点之后只有新模型可写。
- 历史迁移只读；所有数据库修改从新的时间戳文件追加。
- D 项只有在 `rg`、运行遥测、合同图、数据库对象图和关键 Journey 均证明无依赖后执行。

### 6.34 模块级共同收尾动作

3. `public/index.ts`：只导出稳定 DTO/Port/Event Contract；禁止导出 Domain Entity、Repository、Pg 类。

5. `application/*`：依赖本模块 Domain 和声明的 Port；不跨模块 import 私有路径。
6. `infrastructure/*`：实现 Port；映射外部异常为标准 Failure；不偷偷修改别的模块数据。
7. `interface/*`：仅将 HTTP/Event/Job 输入映射到 Operation；不放业务规则。
8. `test/*`：至少包含 Domain 不变量、Application 用例、Persistence 合同、Operation 合同、Scope/权限、幂等/并发和故障测试。
9. 删除模块内 `Helper`、`Utils`、`Common`、`Manager`、`Service` 等无明确职责类；确有领域服务时以行为命名。

## 7. 数据库：只新增可验证迁移，绝不改 316 个历史迁移

### 7.1 迁移总规则

- 历史截止点 `database/migrations/20260903116000_publish_contract_identity.sql` 以前的文件全部只读；任何修正通过新迁移完成。
- SQL 是命名例外，继续 `YYYYMMDDHHMMSS_meaningful_name.sql` 和 `snake_case`；迁移名必须描述结果，禁止 `fix2`、`temp`、`final`。
- 每组硬切按 `prepare → backfill → assert → publish → retire` 排序。`assert` 任一不变量失败必须中止，不能“尽量迁移”。
- Expand 阶段允许新旧数据结构同时存在，仅供迁移程序读写；Publish 当次切全部代码，Retire 立即撤销旧入口和权限，不建立长期双写/兼容视图。
- DDL 使用在线能力：先加 nullable/索引并发构建，再回填，再 `NOT VALID` 约束验证，再设 `NOT NULL`；大表按主键游标分批。
- 每个事务表补齐 `tenant_id`、Scope 列、`version`、UTC 时间、Actor、业务唯一键；金额固定 minor unit + currency。
- 所有 Schema 启用最小权限角色和 RLS；应用角色禁止写其他模块 Schema，Migration Role 不参与运行时。

## 19. 使用本清单时的唯一执行口径

1. 本文件回答“改哪些代码”；`docs/福利商城理想方案20260904.md` 回答“为什么、目标架构与时序是什么”。两者必须同步评审。
2. 遇到实现细节冲突，按：工作簿 MVP → 当前业务功能清单的真实功能 → 理想方案裁决 → 本文件路径建议 → 当前代码的可证明事实。路径可因实际代码微调，领域所有权和不变量不可被便利性推翻。
3. 本清单不是让一次巨型 PR 同时改完；必须按第 15 节分包，但在 P23 之前不能宣称全系统验收完成。
4. 不为旧接口、旧目录、旧状态、旧数据库表或 LI 构建产物保留永久兼容层；迁移窗口代码在 Retire 同包删除。
5. 复用指保留经测试的业务实现、视觉意图和基础能力，不指复制 Mock、重复配置、大文件或错误架构。
6. 如果某项在实现中决定不做，必须回到权威工作簿和本理想方案重新裁决；不能仅隐藏按钮、标记 nonblocking 或写“后续完成”。
7. 最终验收只看可重复证据，不看代码量、页面截图数量、接口存在数量或人工口头确认。
