# 筑大团福利商城业务功能清单

> 基于当前工作区代码整理，更新时间：2026-08-31。  
> 本文只列业务功能，不包含系统架构、接口、数据库、任务框架、监控、日志、部署等技术内容。

## 1. 清单口径

| 状态          | 含义                                                     |
| ------------- | -------------------------------------------------------- |
| 已开放        | 统一登录等跨端页面已经可直接使用。                       |
| 商城已开放    | 员工可在当前商城页面直接使用。                           |
| 运营端已开放  | 有权限的运营人员可在当前控制台页面直接查询或操作。       |
| 只读/部分开放 | 当前页面可查看，或只开放了该业务流程中的一部分动作。     |
| 后台已具备    | 服务端已有业务处理能力，但当前页面没有对应入口。         |
| 自动执行      | 由系统在业务事件发生后或按周期自动推进。                 |
| 条件开放      | 需要指定身份、权限、业务范围、二次验证或双人复核后使用。 |
| 已执行        | 该项为当前业务流程中已经生效的规则。                     |
| 未开放        | 当前页面存在预留位置，但没有可执行的完整业务能力。       |

当前业务覆盖以下使用方和管理范围：

- 员工会员：浏览商品、使用企业福利、下单、支付、查询订单和申请售后。
- 企业运营人员：管理企业范围内的商城、商品、订单、卡券、财务、报表、客服、会员和权限。
- 商城运营人员：管理单个商城范围内的经营、商品、订单和服务配置。
- 平台运营人员：查看组织层级，治理平台商品池、渠道和卡券资产。
- 分销运营人员：查看和管理分销商、推广商品、推广人员、归因和佣金。
- 财务、客服、风控及审核人员：按授权范围处理资金、服务和高风险业务。

## 7. 关键业务规则

- 数据和操作按平台、分销商、企业、商城、部门、门店、供应商、品牌及会员本人范围隔离。
- 同一账号可以拥有多个企业或商城身份，但只能在当前选定身份和授权范围内查看、消费或管理。
- 商品展示价格只用于导购；下单前会重新校验商品、SKU、价格、库存、购买资格、福利余额、卡券、优惠和运费。
- 实物商品必须有有效收货地址；虚拟券、电影票、充值、餐饮和门店服务按各自履约规则处理。
- 福利账户、餐补、卡券和个人支付可组合结算，支付成功后才正式确认订单资金状态。
- 订单、支付、履约和售后分别维护状态，页面不会用其中一个状态推断其他状态。
- 售后可申请数量、期限、是否需要退货和预计退款金额均在申请时重新计算。
- 退款按原支付媒介拆分，并同步处理福利、卡券、财务、报表和返佣冲正。
- 推广关系按首次归因规则建立；订单支付、收货和退款分别驱动佣金创建、可用、结算和冲正。
- 财务金额以不可变业务分录、对账、结算和开票记录为准，页面不自行计算最终资金结论。
- 普通员工不能自助获得管理员权限；所有者转移、权限、资金、分销规则等高风险操作需要更高等级验证，部分还要求另一名管理员复核。
- 当前页面只读或未开放的动作，不代表后台没有能力；实际可用范围同时受企业配置、业务权限、数据范围和当前身份验证等级控制。
