## 真实责任

迁移在单一事务中把legacy公共模型投影到组织、身份、成员、库存、订单、支付、退款、券、权益、财务、渠道、事件、死信、审计和报表等领域。它保留来源时间、身份状态、幂等键和事件投递状态，而非只复制当前业务表。

对分销联系人与微信身份，迁移先要求runtime secure-stage与来源记录数量/关联完全一致，缺失即fail-closed；密码、手机号、TOTP及联邦身份也按各自目标安全模型投影。这些是不可由普通运行代码重新推导的历史状态。

## 序列边界

数据库契约计划将该文件固定为全域repair序列的一部分，紧接后继对账迁移，并在随后legacy对象退役前作为目标模型的历史输入。库存样本也证明早期库存切换数据被转换到当前domain model；事件样本保留outbox、inbox、deadletter和audit链。

## 裁决与未知项

维持GX。删除或单独重放会脱离同序列的源表、secure-stage、对账和维护窗口，可能造成历史资金、身份、事件或审计不一致。未读取生产migration ledger、实际行数/金额/hash对账、密钥stage、备份或恢复演练；这些必须在授权后的隔离副本专项验证。本审计分支未执行迁移或改变数据。
